# Fluidd 界面

ACE Pro 管理中心提供三个界面入口。它们读取同一份 Klipper 状态、Moonraker 能力和动作 API，不会各自维护一套换料状态。

| 入口 | 地址或位置 | 用途 |
| --- | --- | --- |
| Dashboard 卡片 | Fluidd 仪表盘 | 查看设备、槽位和路径状态，执行常用操作 |
| ACE Pro 页面 | `#/acepro` | 完整控制、库存、维护、诊断和恢复 |
| 静态备用页 | `/ace-v3/` | Fluidd 源码无法集成或尚未重新构建时使用 |

## Dashboard 卡片

卡片沿用 V2 的信息顺序，主要区域为：

1. 当前设备连接状态、型号、运行状态和温度。
2. 烘干状态及启停控制。
3. 四个槽位的工具号、材料、颜色、温度、RFID 和装载状态。
4. 手动送料、回料和 ACE 内置辅助送料。
5. 总五通、共享编码器、上方传感器、下方传感器和当前耗材路径。
6. 刷新、卸载、库存保存、诊断和无限续料等快捷操作。

卡片菜单中的“打开页面”进入 `#/acepro`。校准、恢复和详细诊断放在完整页面中，不占用 Dashboard 的日常操作区域。

## 设备切换与工具号

每台 ACE 固定对应四个全局工具号：

| 设备 | 工具号 |
| --- | --- |
| ACE 1（`ace0`） | `T0-T3` |
| ACE 2（`ace1`） | `T4-T7` |
| ACE 3（`ace2`） | `T8-T11` |
| ACE 4（`ace3`） | `T12-T15` |

只有一台 ACE 时，卡片隐藏设备切换按钮，Fluidd 原生工具区只显示 `T0-T3`。配置两台及以上时，标题下方显示连续的 `ACE 1` 至 `ACE 4` 切换按钮；每次只显示当前设备的四个槽位和动作目标。

驱动为了兼容切片文件，始终在 Klipper 中注册 `T0-T15`。这不表示单 ACE 界面应显示 16 个通道。原生工具区必须根据 `ace.device_count` 裁剪为 4、8、12 或 16 个按钮，并按每台设备一行四列排列。

如果 ACE 状态对象缺失、设备数无效或前端无法读取 `device_count`，补丁不会猜测设备数量，而是保留 Fluidd 原有工具分组。此时请按[故障排查](Troubleshooting#单-ace-却显示了更多工具号)检查状态和前端构建。

## 路径与传感器显示

单 ACE 的路径显示为：

```text
ACE -> 总五通 -> 共享编码器（可选） -> 上方传感器 -> 挤出机 -> 喷嘴
                                                               └-> 下方传感器（可选只读）
```

单 ACE 不使用一级五通，界面也不会显示一级五通项目。两台至四台 ACE 时，每台设备增加自己的一级五通分支；总五通、共享编码器和打印头侧传感器仍是全局共享状态，切换设备不会重置它们。

传感器引脚留空时显示“未配置”。“未配置”与“无料”不同：前者表示没有启用该传感器，后者表示已配置的传感器当前检测不到耗材。编码器无脉冲也不能单独判定为无料。

下方传感器不是通用必装项。`toolhead_sensor_bypass: True` 时显示“仅监测 · 有料/无料/未配置”；显式设为 `False` 时显示“参与控制 · 有料/无料/未配置”及对应就绪或故障状态。

编码器选择 `protect` 但因未校准、不可用或存在故障而尚未 armed 时，界面使用黄色“保护 · 未启用”，表示保护条件未满足，不表示正在运行或已经发生故障。卡片和完整页面同时显示上方送料总超时、挤出机标定距离及最低跟随比例，便于核对就绪条件。

RFID 默认开启，但协议未识别到有效标签时显示“已关闭”，避免把无标签卷料持续显示为故障。关闭 RFID 不会清除手工填写的材料、颜色和温度。

## `#/acepro` 完整页面

完整页面复用 Dashboard 的设备与槽位状态，并默认展开维护和诊断区域，包括：

- 全局打印状态、当前工具、共享路径锁和活动事务。
- 设备连接、协议、固件、温度、烘干和四槽库存。
- 换料、卸载、手动送料、手动回料和辅助送料。
- 无限续料的全局设置与候选槽位。
- 共享编码器状态、默认 `150 mm x 3` 分段校准、一致性判定和取消操作。
- 连接、槽位、传感器、编码器故障现场及恢复建议。

页面不提供任意 G-code 输入框。所有按钮都先读取能力接口，再通过结构化动作 API 提交；API 失败时不会改用控制台原始 G-code。

## `/ace-v3/` 静态备用页

安装器始终部署 `/ace-v3/`。它不依赖 Fluidd Vue 源码，但与原生卡片和 `#/acepro` 使用相同的状态模型与 Moonraker API。

以下情况优先使用备用页：

- Fluidd 版本或源码结构不在当前支持范围内。
- 安装器以 `--fluidd-mode standalone` 运行。
- `auto` 模式检测到不兼容并自动跳过源码补丁。
- Fluidd 源码已打补丁，但尚未完成生产构建和 `dist` 部署。
- 原生页面出现缓存或路由问题，需要判断后端是否正常。

备用页地址示例：

```text
http://printer.local/ace-v3/
```

## Fluidd 集成模式

| 模式 | 行为 |
| --- | --- |
| `auto` | 源码兼容时安装 Dashboard 卡片和 `#/acepro`；不兼容时保留 `/ace-v3/` |
| `source` | 强制源码集成；版本、锚点或路由冲突时在写入前失败 |
| `standalone` | 不修改 Fluidd 源码，只部署 `/ace-v3/` |

原生集成完成后，仍需按照该 Fluidd 版本自己的 Node 和包管理器要求重新构建并部署 `dist`。安装器不会自动升级 Node，也不会自动重启 Fluidd。

原生页面只有在以下步骤全部完成后才算已部署：overlay 应用成功、目标 Fluidd 生产构建成功、新 `dist` 已复制到实际 Web 根目录、浏览器可打开 Dashboard 卡片和 `#/acepro`。只看到源码文件已修改不算完成。构建或部署失败时先使用 `/ace-v3/` 检查后端，再按安装器输出的持久快照恢复 Fluidd 源码与产物。

## 操作门禁

按钮是否可用由后端最终决定。界面会显示阻塞原因，常见情况包括：

- 自动换料仍为手动模式，或七个机器动作宏未配置完整。
- 目标设备离线、只读或未启用物理动作。
- 当前槽位为空或不可用。
- 打印状态不允许该动作。
- 共享耗材路径已有事务正在运行。
- 编码器未配置、未校准，或校准条件不满足。

危险动作必须显示目标设备、工具和确认原因。刷新页面、网络重连或浏览器恢复不会自动重提上一个物理动作。
