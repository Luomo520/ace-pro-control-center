# 传感器和编码器

Ace Pro Control Center 第三代驱动以上方传感器确定 ACE 与挤出机的交接位置，以五通传感器确认共享路径是否释放，并使用一个可选共享编码器判断耗材是否真实移动。下方传感器不是通用安装必需项：默认旁路并仅监测，用户确认稳定后可显式恢复闭环。

> **接线警告：** 不同主板、工具板和 MCU 的引脚、电压与触发电平不同。禁止照搬其他打印机的引脚。接线和修改引脚前应断开相应电源并核对硬件资料；首次验证保持 `toolchange_mode: manual` 和 `physical_actions_enabled: False`，不执行送料、回料或切刀。

## 路径位置

### 单 ACE

```text
ACE0 四槽 -> 总五通 -> 可选共享编码器 -> 上方传感器 -> 挤出机 -> 喷嘴
                                                                    └-> 可选下方传感器（只读）
```

单 ACE 没有一级五通，也不创建一级五通传感器对象。

### 多 ACE

```text
ACE0 四槽 -> 一级五通 0 --\
ACE1 四槽 -> 一级五通 1 ---+
ACE2 四槽 -> 一级五通 2 ---+--> 总五通 -> 可选共享编码器 -> 上方传感器 -> 挤出机 -> 喷嘴
                                                                                       └-> 可选下方传感器（只读）
ACE3 四槽 -> 一级五通 3 --/
```

共享编码器必须位于总五通之后、上方传感器之前，使所有 ACE 分支都经过同一个测量点。ACE 内置缓冲和张力调节属于设备内部机构；V3 不把它配置成独立节点，也不套用 Happy Hare/AFC 的外置缓冲、压缩或张力传感器模型。

## 用户只填写引脚

新配置不需要填写传感器名称。V3 使用固定内部名称创建对象：

| 用户配置项 | 内部对象 | 位置 |
| --- | --- | --- |
| `extruder_sensor_pin` | `extruder_sensor` | 挤出机之前的上方传感器 |
| `toolhead_sensor_pin` | `toolhead_sensor` | 挤出机与喷嘴之间的下方传感器 |
| `rdm_sensor_pin` | `rdm_sensor` | 共享总五通传感器 |
| `aceN_hub_sensor_pin` | `aceN_hub_sensor` | 多 ACE 的对应一级五通传感器 |
| `encoder_sensor_pin` | `shared_encoder` | 总五通之后的共享编码器 |

引脚为空表示该传感器未安装或停用：

```ini
extruder_sensor_pin:
```

这不会阻止 Klipper 启动。只有用户填写真实引脚后，V3 才会动态创建对应对象。旧配置中的 `*_sensor_name` 只用于升级兼容，新用户不要添加这些字段。

Klipper 引脚可以按硬件需要使用 `^` 上拉和 `!` 反相修饰符，但必须根据本机电路确认：

```ini
extruder_sensor_pin: <可选修饰符><MCU 名称>:<真实引脚>
```

上面是格式占位符，不能直接使用。

## 开关传感器配置

```ini
[ace]
extruder_sensor_pin: <上方传感器真实引脚>
extruder_sensor_debounce_count: 2

toolhead_sensor_pin: <可选下方传感器真实引脚；未安装时留空>
toolhead_sensor_debounce_count: 2
toolhead_sensor_bypass: True
toolhead_sensor_bypass_load_length: 25
upper_sensor_feed_timeout: 30

rdm_sensor_pin: <总五通传感器真实引脚>
rdm_sensor_debounce_count: 3

ace0_hub_sensor_pin: <多 ACE ace0 一级五通传感器真实引脚>
ace1_hub_sensor_pin: <多 ACE ace1 一级五通传感器真实引脚>
ace2_hub_sensor_pin: <多 ACE ace2 一级五通传感器真实引脚>
ace3_hub_sensor_pin: <多 ACE ace3 一级五通传感器真实引脚>
ace_hub_sensor_debounce_count: 3
```

未安装的行保持为空，不要填写占位符。

### 去抖计数

`*_debounce_count` 表示状态需要连续确认多少次，并不是毫秒数。较大值可以过滤接点抖动，但也会增加动作停止前的确认时间。

- 上方、下方传感器默认建议从 `2` 开始。
- 总五通和一级五通默认建议从 `3` 开始。
- 只有在观察到真实抖动时才逐步增加。
- 不要用很大的去抖值掩盖松动接线、错误触发电平或机械接触不良。

### 各传感器职责

#### 上方传感器

位于公共路径进入挤出机之前，是 ACE 与挤出机之间唯一的控制权交接点。

- 装载时，只有上方传感器稳定触发才表示 ACE 送料成功；触发后立即停止 ACE。
- 卸载时，先由挤出机回抽，直到上方传感器稳定释放，再交给 ACE 回抽五通路径。
- 自动换料要求上方传感器已配置、可读取并完成空料/有料验证。

`toolchange_load_length` 和 `feed_slip_compensation_length` 是发送给 ACE 固件的参考量，不能相加当作真实送料上限或到位距离。驱动把 ACE 送料拆成最长约 `2` 秒的受限窗口：先消耗主参考量，再使用低速补偿参考量；两者耗尽后仍以补偿速度继续分段寻找上方传感器。`upper_sensor_feed_timeout` 默认 `30` 秒、有效范围 `1..120` 秒，是整个 ACE 寻位阶段唯一的最终硬截止；达到截止时间仍未触发时会停止 ACE，截止后的迟到信号不算成功。

ACE 固件若提前报告当前窗口完成，驱动仍会在不超过总截止时间的前提下保留传感器触发宽限。读取上方传感器或等待动作期间发生异常时，驱动会先发送停止送料，再把本次动作作为失败处理。

#### 下方传感器

位于挤出机与喷嘴之间，但不是通用安装必需项。`toolhead_sensor_bypass: True` 是默认值：未安装时引脚留空，已安装时持续显示原始状态，但不参与必要判定。用户确认接线、去抖和完整装卸均稳定后，可显式设为 `False` 恢复下方闭环；此时其触发、释放及闭环距离参与动作和就绪判定。

#### 上方交接点到喷嘴

上方传感器稳定触发后，ACE 停止送料，后续由挤出机步进电机执行本机标定距离：

```ini
[ace]
toolhead_sensor_bypass_load_length: <上方交接点到喷嘴目标位置的实测毫米数>
```

该键名为兼容旧配置暂时保留，只表示挤出机控制段，不表示下方传感器旁路，也不表示 ACE 精确移动了相同距离。模板中的 `25 mm` 是未校准样板，不是可直接使用的默认值；新安装即使看到 `25`，自动换料也必须保持未就绪。保持手动模式和打印机待机，按材料要求加热热端，让耗材停在上方传感器刚稳定触发的位置，再由挤出机低速、小步长送到喷嘴目标位置并记录命令距离；完整卸载后至少重复三次并明确保存校准结果。填写 `0` 同样表示尚未标定；`250 mm` 是防止误填的解析硬上限，不是建议距离，超过该值直接拒绝配置。

编码器安装在公共路径时，挤出机接管期间也应产生脉冲。`monitor` 下无脉冲只提示，打印和动作结论不变；`protect` 下无脉冲必须停止，且不能把路径标记为已装载。这可以把排查范围缩小到上方传感器附近、耗材未进入挤出齿轮、齿轮未咬料或发生打滑，但不能自动断言具体故障。

#### 总五通传感器

无论设备数量，总五通都只有一个。旧字段前缀保留为 `rdm_*`，但界面统一显示“总五通传感器”。

- 单 ACE：可安装；未安装时，停放依赖实测的共享回抽距离。
- 多 ACE：自动换料必须配置总五通传感器，用于确认公共路径已经释放。

传感器必须覆盖所有分支汇合后的唯一公共路径，不能安装在只经过某一台 ACE 的分支上。

#### 一级五通传感器

只供 2 至 4 台 ACE 使用。每个分支可以安装，也可以留空：

- 有传感器时，`aceN_hub_retract_length` 是寻找该传感器释放的最大距离。
- 无传感器时，`aceN_hub_retract_length + aceN_hub_clear_move_length` 形成该分支的受限盲回退。
- 单 ACE 即使旧配置残留一级五通引脚，运行时也会忽略。

详细拓扑和校准见 [多 ACE](Multi-ACE)。

## 传感器安全验证顺序

每次只配置和验证一路传感器：

1. 确认打印机待机，保持 `manual` 和所有设备物理动作门禁关闭。
2. 核对 MCU 名称、实际引脚、电压和接线方式，再填写一个 `*_sensor_pin`。
3. 重启 Klipper，执行 `ACE_GET_STATUS`，确认该传感器显示为已提供且没有注册错误。
4. 无耗材时记录状态；用手插入耗材，确认状态稳定变为有料；再抽出，确认恢复无料。
5. 如果状态完全相反，先重新核对常开/常闭接线，再按 Klipper 规则决定是否使用 `!`，不要直接猜测反相。
6. 连续重复多次，轻微晃动接头，确认不会随机跳变；有抖动先修复机械和接线，再调整去抖计数。
7. 该路通过后再配置下一路。上方和当前拓扑所需五通传感器完成手动验证前，不执行自动送料或回抽；下方传感器未安装不影响继续。
8. 最后在低速、可立即停止的动作中确认上方传感器触发会停止 ACE、上方释放会完成挤出机回抽交接、五通传感器会终止相应回抽阶段。下方传感器只核对原始状态，不把其变化作为停止条件。

若界面显示“未提供”，通常表示引脚为空、动态对象没有成功创建或旧名称配置冲突；不要通过填写任意引脚消除提示。

## 共享编码器

V3 全系统只允许一个共享编码器：

```text
所有 ACE 分支 -> 总五通 -> 共享编码器 -> 上方传感器 -> 挤出机
```

编码器只回答“耗材有没有移动、移动了多少脉冲”。它同时观察 ACE 寻找上方传感器的阶段和挤出机接管后的送料/回抽阶段，但不能单独回答耗材位于哪个绝对位置，也不会：

- 替代上方、总五通或一级五通传感器；下方传感器本来就是可选观测点。
- 无上限自动追加送料或把 ACE 命令距离当成真实欠料距离。
- 判断槽位是否为空。
- 自动从堵料、断料或未知路径中恢复。

## 编码器配置项

```ini
[ace]
encoder_sensor_pin: <共享编码器真实脉冲引脚>
encoder_resolution: 0
encoder_detection_length: 20
encoder_min_tracking_ratio: 0.6
encoder_mode: off
encoder_print_mode: off
encoder_print_detection_length: 20
```

| 参数 | 说明 |
| --- | --- |
| `encoder_sensor_pin` | 编码器脉冲输入；留空表示未安装 |
| `encoder_resolution` | 每个脉冲对应的毫米数；`0` 表示尚未校准 |
| `encoder_detection_length` | 编码器长窗口阈值，不是 ACE 到位距离；达到该长度的动作至少需要两个有效脉冲，短动作也不允许零脉冲 |
| `encoder_min_tracking_ratio` | 最低允许跟随比例，默认 `0.6`，有效范围 `0.01..1` |
| `encoder_mode` | ACE 寻位及挤出机接管动作监测模式 |
| `encoder_print_mode` | 打印中的连续耗材运动监测模式 |
| `encoder_print_detection_length` | 打印净挤出达到该距离仍无新脉冲时报告故障 |

所有长度都必须是有限正数，`encoder_resolution` 未校准时保持 `0`。第一次安装应让两种模式都保持 `off`。

## ACE 动作监测的三种模式

`encoder_mode` 有三个值：

| 模式 | 行为 | 适用阶段 |
| --- | --- | --- |
| `off` | 不建立运动判断 | 未安装、未接线、未校准或首次检查 |
| `monitor` | 在 ACE 寻位和挤出机接管段记录脉冲、测量距离和跟随结果，无进展只提示 | 校准后观察和本机验证 |
| `protect` | 检测窗口内仍未确认运动时中止当前阶段，把路径置为需要人工检查；挤出机段不得标记已装载 | 完成真机验证后使用 |

`monitor` 还必须保持路径语义不变：故障只显示和记录，不改变自动换料就绪、当前工具或路径状态，也不要求重连时读取路径传感器。执行 `ACE_RECONNECT` 时可以清除该观察故障；只有 `protect` 故障会进入路径恢复流程。Fluidd 卡片以蓝色“监测 · 只读”显示该状态。

每个 ACE 受限送料窗口都会单独检查脉冲，因此可以识别“开始移动后中途停止”。短于 `encoder_detection_length` 的窗口只做有无运动判断，但零脉冲仍会报告异常；达到或超过该长度的窗口至少需要两个有效脉冲。`encoder_detection_length` 不表示耗材应该到达哪个传感器，也不能替代 `upper_sensor_feed_timeout`。

`protect` 只有在编码器可用、分辨率已校准且当前无编码器故障时才会处于 armed 状态。选择 `protect` 但尚未 armed 时，Fluidd 以黄色“保护 · 未启用”提示，自动换料保持“尚未就绪”。挤出机接管段还必须保证本次可执行运动距离不短于 `encoder_detection_length`；不满足时在任何挤出机或 ACE 物理动作前拒绝该次换料。`protect` 异常会作为普通 G-code 错误返回，不应变成 Klipper 内部错误或触发 MCU 关机。

## 打印监测的三种模式

`encoder_print_mode` 独立于 `encoder_mode`：

| 模式 | 行为 |
| --- | --- |
| `off` | 不监测打印中的连续耗材运动 |
| `monitor` | 达到阈值且没有新脉冲时记录一次故障并提示，打印继续 |
| `pause` | 记录故障，并通过 `_ace_pause_on_toolchange_error` 请求一次暂停 |

打印监测只在以下条件同时满足时活动：

- `print_stats` 为 `printing`。
- 当前工具已装载，路径状态有效。
- 没有换料事务正在占用共享路径。
- 编码器不在校准中。
- 编码器计数和挤出机物理位置可读取。

驱动按净挤出累计。回抽先形成负债，随后的等量恢复只抵消负债，不会被当成新的耗材消耗。检测到新脉冲后重新获得完整检测余量。同一次无脉冲故障不会重复暂停。

打印监测只判断是否出现新脉冲，因此不依赖毫米/脉冲分辨率；但完成校准仍有助于确认编码器机械和计数工作正常。故障不会触发自动补料、距离补偿或自动恢复。

## 三段式人工校准

校准不会驱动 ACE 或挤出机，耗材由用户手动推动。开始前必须满足：

1. 打印机待机，不在打印或暂停打印中。
2. 当前工具已经卸载。
3. 共享路径状态为 `empty`，不是 `unknown`。
4. ACE 辅助送料已经关闭。
5. 编码器引脚已配置，并能在 `ACE_ENCODER_STATUS` 中观察到脉冲变化。
6. `encoder_mode` 和 `encoder_print_mode` 先保持 `off`。

默认校准参数为每段 `150 mm`、共 `3` 段。三段使用同一段耗材连续移动或重新定位均可，但每段都必须准确量取并单独提交，不能把三段合并成一次 `450 mm` 测量。

### 第一步：开始第一段

```gcode
ACE_ENCODER_CALIBRATE START=1
```

也可以在 Fluidd 完整页点击“开始校准”。执行后，用手准确推动耗材通过编码器。每当计数增加，Fluidd 控制台同步输出“本段新增、校准累计、硬件累计”三个数值；耗材静止时不会重复刷屏。

### 第二步：逐段提交真实长度

每段默认准确移动 `150 mm`，然后提交该段真实长度：

```gcode
ACE_ENCODER_CALIBRATE LENGTH=150
```

驱动记录该段脉冲数与 `mm/脉冲`，随后开始下一段。重复移动和提交，直到完成默认 `3` 段。`LENGTH` 必须是有效有限数值；任一段脉冲不足、长度无效或前置状态改变时整轮校准失败，不保存结果。

### 第三步：检查一致性并保存

三段完成后比较各段分辨率：

| 最大段间偏差 | 处理 |
| --- | --- |
| `<=5%` | 校准通过并允许保存 |
| `>5%` 且 `<=10%` | 显示机械打滑或测量误差警告；用户明确确认后才允许保存 |
| `>10%` | 拒绝保存，检查压轮弹簧、编码轮压力、接线、计数和测量方法后重做 |

校准段长是为了获得稳定分辨率，不能用于运行时打滑检测。ACE 动作继续使用 `encoder_detection_length` 短窗口，打印继续使用 `encoder_print_detection_length` 短窗口；不要把它们改为 `150 mm`。

校准结果保存到 V3 运行状态，不会改写 `ace.cfg`。因此文件中的 `encoder_resolution: 0` 仍可能与运行状态中的已校准分辨率并存，应以 `ACE_ENCODER_STATUS` 的当前状态为准。

### 取消未完成校准

```gcode
ACE_ENCODER_CALIBRATE CANCEL=1
```

取消不驱动电机，也不清除上一次已经成功保存的分辨率。从 `START=1` 到完成或取消之间，驱动会拒绝新的 ACE 运动、辅助送料启用和自动换料，避免无关脉冲混入；停用已经开启的辅助送料仍允许。完成或取消后，控制台立即停止校准计数输出。

每条校准命令只能提供 `START`、`LENGTH`、`CANCEL` 中的一项。

## 编码器启用与验证顺序

1. **接线阶段**：只填写 `encoder_sensor_pin`，保持两个模式为 `off`，重启并检查对象可用。
2. **被动计数阶段**：执行 `ACE_ENCODER_STATUS`，手动正向、反向推动耗材，确认脉冲稳定增加且没有静止乱跳。
3. **校准阶段**：按默认 `150 mm x 3` 完成分段测量，检查每段脉冲、分辨率和 `5%/10%` 一致性判定。
4. **观察阶段**：设置 `encoder_mode: monitor`，在待机状态用低速、短距离 ACE 动作观察跟随结果，不改变动作结论。
5. **保护阶段**：只有正常送料和回料都稳定后，才使用无打印、短距离、可立即停止的受控测试验证无脉冲故障；不要用堵死喷嘴或强行夹住耗材作为测试。通过后再考虑 `protect`。
6. **打印观察阶段**：先使用 `encoder_print_mode: monitor` 完成短打印，确认回抽不会误报、阈值适合实际挤出。
7. **打印暂停阶段**：只有 monitor 没有误报且错误宏已经验证时，才切换为 `pause`，并完成一次不损伤机器的受控暂停测试。

任何阶段出现脉冲丢失、静止乱跳、分辨率差异过大或传感器状态矛盾，都退回 `off` 排查机械压紧、轮径、接线、引脚、电平和路径阻力。

## 状态检查

```gcode
ACE_GET_STATUS
ACE_ENCODER_STATUS
```

重点检查：

- 传感器是否显示 configured/available，而不是仅在文件中有文本。
- 上方和五通的无料/有料状态是否符合实际；下方若安装，只核对显示，不把它当作就绪条件。
- 编码器 `available`、`calibrated`、`resolution` 和 `armed` 是否符合当前阶段。
- `encoder_mode` 与 `encoder_print_mode` 是否仍处在计划中的安全等级。
- 最近故障是否与当时工具、路径和传感器快照一致。

## 当前验证边界

- “上方传感器唯一交接、下方传感器可选、ACE 受限窗口持续寻位、总超时硬截止、挤出机定距接管和编码器双阶段保护”已经完成代码、配置模板和本地自动化验证。
- 本地验证不等于真机动作验收。上方交接点到喷嘴的挤出机距离必须按本机重复测量；完成完整装卸、停止和故障测试前，不得用于正式多色打印。
- 共享编码器脉冲计数、默认 `150 mm x 3` 校准和 `5%/10%` 一致性门禁已完成软件自动化验证。ACE/挤出机段 `monitor`/`protect` 及打印 `monitor`/`pause` 仍需在目标机核对真实脉冲、短窗口阈值和停止行为。
- 多 ACE 一级五通及跨设备动作尚未在具备相应硬件的真机上验收，不能把模拟通过写成物理路径已验证。

设计来源：Happy Hare 固定提交 `73d39aab2110deebb64dfb7899c6838a706edcea` 提供入口归位、入口到喷嘴定距和编码器运动验证经验；AFC 固定提交 `a06f14dd5b2aa5e2878f92cef7a07f1e8b1fd5a3` 提供只有入口传感器、工具端传感器可为空时的职责划分。V3 只借鉴设计，不复制代码或外置缓冲器模型。
