# Ace Pro Control Center | ACE Pro 管理中心：第三代决策记录

本文件是 V3 的产品和技术基线。若后续改变，必须追加新的决策并说明替代原因；实现状态和部署状态记录在 `PROJECT_MEMORY.zh-CN.md`。

## ADR-001：`Kobra-S1/ACEPRO` 作为代码地基，SV08 作为行为与界面基线

**决定：** 不从 SV08 的单文件直接派生。使用 `Kobra-S1/ACEPRO` 的模块化结构作为后端起点，同时以 `ACEPROSV08` 核对 ACE1 协议、动作顺序和界面布局。

**原因：** V3 的多 ACE、ACE1/ACE2 混用、`T0-T15` 和设备级状态是硬性需求。SV08 只有单设备模型，继续扩展会重写串口、状态、命令和库存。`Kobra-S1/ACEPRO` 已有 `Manager -> Instance -> Protocol` 分层和对应测试。

**限制：** `Kobra-S1/ACEPRO` 不是可直接发布的通用驱动。其 Kobra 配置、宏、引脚和部分实验功能必须剔除或改成 V3 机器适配层。

## ADR-002：通用 Klipper 优先

驱动核心不得写入以下内容：

- Kobra S1/K3 或 SV08 专属引脚、MCU 名称和串口猜测。
- 固定打印头坐标、切刀坐标、停靠坐标、擦嘴路径和固定温度。
- 默认存在的厂家宏、Fluidd 私有对象或 KlipperScreen 私有对象。
- 任何只在特殊 Klipper 分支存在的 API。

机器相关动作只能通过 `ace.cfg` 中的七个 `_ace_*` 宏或适配器调用。没有配置或校准机器钩子时，驱动必须安全跳过或报告“未配置”，不得自行猜测运动。

## ADR-003：一打印头、多 ACE

最多 4 台 ACE 共享一个打印头和一条耗材路径。系统只有一个全局当前工具、一个路径锁和一个换料事务；不同 ACE 不得并发驱动打印头。

## ADR-004：逻辑编号稳定优先于物理发现顺序

`ace0..ace3` 的配置顺序决定 `T0..T15` 映射。设备断线、USB 重枚举或重启不得改变工具编号。

物理识别顺序按以下优先级处理：

1. 用户配置的稳定串口路径和 ACE2 UID。
2. 配置声明的设备类型。
3. USB `LOCATION` 仅用于发现、校验和诊断，不得自动改写逻辑编号。
4. `/dev/ttyACM*` 仅作为临时提示，不得作为永久身份。

## ADR-005：ACE2 能力门禁

ACE2 可以参加配置、状态模型、库存映射和界面展示，但首版 `physical_actions_enabled` 强制为 `False`。发送、回抽、换料、助推和烘干等物理命令必须在协议层和管理层双重拒绝，直到 ACE2 真机验收完成。

## ADR-006：运行时采用单文件配置

**决定：** `printer.cfg` 只 include `ace.cfg`。`ace.cfg` 是唯一活动 ACE 配置，内部依次包含安装器托管的硬件拓扑、共享参数、机器钩子和机器宏。不得继续 include `ace_hardware.cfg`、`ace_machine.cfg` 或任何迁移归档。

设备拓扑与机器动作仍保持清楚的文件内区域边界：安装器管理设备数量、逻辑设备、型号、稳定串口、ACE2 总线、UID 和设备能力；用户配置共享打印头、传感器引脚、路径距离、速度、安全策略、耗材候选、`[ace_machine]` 和七个机器适配宏。单文件只消除运行时碎片，不允许安装器覆盖用户校准值，也不允许机器宏污染硬件拓扑块。

**迁移：** 旧 `ace_hardware.cfg` 只允许由安装器读取一次。有效设备身份、通信参数和安全开关合并进 `ace.cfg` 后，原文件归档到配置目录的 `.ace-driver-v3/legacy/`，同时移除旧 include；归档只用于追溯和恢复。旧 `ace_machine.cfg` 同样只作为迁移输入，其宏与校准值合并进 `ace.cfg` 后退出运行链。新安装不创建这两个拆分文件。

**重装：** 增删 ACE、替换型号或改变 ACE1/ACE2 组合仍必须重新运行安装器。安装器可以重建硬件拓扑块，但必须按稳定串口身份，或 ACE2 的总线与 UID，保留同一物理设备的 `enabled`、`rfid_enabled` 和 `physical_actions_enabled`；设备换序不得串位，新设备不得继承被移除设备的授权。

## ADR-007：V2 管理中心与设备切换作为用户体验契约

每次只显示一台 ACE 的完整 V2 管理中心：顶部状态、设备与烘干、四槽管理、手动送料和快捷操作。配置多台设备时在顶部增加 ACE 切换按钮，不纵向堆叠多套控制区，也不压缩成难以操作的总库存表。单设备时隐藏切换按钮。

界面只消费结构化状态和能力，不直接拼接底层 G-code；能力不可用时按钮禁用并显示原因。

## ADR-008：两款上游驱动的功能取舍

| V3 功能 | 主要来源 | V3 处理 |
| --- | --- | --- |
| 多设备编排、设备实例、跨设备库存 | `Kobra-S1/ACEPRO` 的 `manager.py`、`instance.py` | 保留分层，改写为通用 Klipper API |
| ACE1 串口传输、队列、重连 | `Kobra-S1/ACEPRO` 的 `serial_manager.py` | 保留机制，删除按厂家描述寻找首个端口的回退 |
| ACE1 帧、CRC、请求 ID、动作 RPC | SV08 的 `extras/ace.py`、`PROTOCOL.md` | 保留并与 `Kobra-S1/ACEPRO` 的 `protocol_ace1.py` 对照测试 |
| ACE2 协议解析 | `Kobra-S1/ACEPRO` 的 `protocol_ace2.py` | 保留协议解析，首版只读，物理命令双重拒绝 |
| ACE2 共享总线、UID | `Kobra-S1/ACEPRO` 的 `ace2_bus.py` | 保留身份和总线抽象，逻辑编号由配置顺序决定 |
| `T0-T15`、全局当前工具、路径锁 | `Kobra-S1/ACEPRO` 的 Manager/commands 设计 | 保留能力，重新实现 V3 命令和安全门禁 |
| 库存持久化、无限续料、运行监控 | `Kobra-S1/ACEPRO` 的独立模块 | 分批接入，先验证 ACE1，功能失败不得影响基础换料 |
| 四槽按钮和换料交互 | V2/SV08 的操作语义与界面 | 保留单设备管理中心，通过设备切换扩展到 1-4 台 |
| Kobra/SV08 引脚、坐标、切刀和打印机宏 | 两者的机器配置 | 只迁移适用的宏行为和用户实测值到 `ace.cfg`，不进入通用 Python 核心 |

因此，V3 不是两个项目的代码拼接，而是以 `Kobra-S1/ACEPRO` 后端架构为骨架、以 SV08 ACE1/界面行为为验收基线的通用重构。

## ADR-009：V2 卡片和独立控制界面纳入 V3

V2 Fluidd 卡片与独立 `ace.html` 控制界面都是 V3 的正式产品组成。保留其布局、库存、烘干、换料、校准、诊断和反馈经验，但统一改用 V3 多设备状态和结构化 Moonraker API。

Fluidd 卡片承担高频日常操作，独立界面承担完整维护与诊断。两者共用前端核心，不得分别维护当前工具、库存和动作策略。V2 的单设备假设、固定 `TOOL=-1..3`、直接 G-code 构造和 API 失败回退必须剔除。

## ADR-010：六个旧机器宏并入 `ace.cfg`，`ace_machine.cfg` 退役为迁移模板

**决定：** 当时的六个 `_ACE_MACHINE_*` 宏统一放入 `config/ace.cfg`，并让 `config/ace_machine.cfg` 退出活动配置。宏命名部分后来由 ADR-011 的七宏契约替代；本条仍保留文件所有权和 legacy 迁移决定。

六个宏为：

- `_ACE_MACHINE_PRE_TOOLCHANGE`
- `_ACE_MACHINE_CUT`
- `_ACE_MACHINE_LOAD_TO_TOOLHEAD`
- `_ACE_MACHINE_UNLOAD_FROM_TOOLHEAD`
- `_ACE_MACHINE_POST_TOOLCHANGE`
- `_ACE_MACHINE_PAUSE_ON_ERROR`

**迁移规则：** 安装器升级时使用 `config_upgrade.py merged`，移除旧 `ace_machine.cfg` include，将旧文件中的宏、校准变量和适用自定义 G-code 合并到 `ace.cfg`，优先保留用户已验证值。合并成功后把旧安装文件归档为 `ace_machine.cfg.legacy`，不得覆盖已有归档。新安装直接使用 `ace.cfg` 中的宏，不创建 `ace_machine.cfg`。

**原因：** 机器动作宏、共享路径和硬件拓扑共同构成一台打印机的运行契约，分散在多个活动文件会造成 include 顺序、迁移覆盖和用户审查上的歧义。设备拓扑仍在 `ace.cfg` 内保持独立的安装器托管区域，因此设备增删和 ACE1/ACE2 组合不会污染机器动作配置。

**限制：** 宏合并不等于物理动作已验证。坐标、温度、清洁和打印机运动仍必须由用户按本机校准；未完成真机验收前，不得将本地迁移测试写成打印机部署成功。

## ADR-011：手动模式、换料就绪状态和机器宏安全模板

**决定：** 设备物理动作能力与自动换料能力分开控制。`ace.cfg` 设备节中的 `physical_actions_enabled` 是单台设备的物理动作总门禁；同一文件的全局 `toolchange_mode` 取值为 `manual` 或 `automatic`。全新安装默认 `toolchange_mode: manual`，并将所有 ACE1 的 `physical_actions_enabled` 写为 `False`。升级或重装按稳定硬件身份保留用户的 `enabled`、`rfid_enabled` 和 `physical_actions_enabled`，设备换序不能串位，新设备不能继承旧设备授权。

手动模式用于只连接 ACE、读取状态和库存，或由用户选择一个槽位使用 ACE 内置辅助送料。缺少停车坐标、切刀坐标、擦嘴宏、路径传感器或换料距离时不得导致 Klipper 配置加载失败，也不得在界面显示为设备故障；驱动只把自动换料标记为“未启用”或“尚未就绪”。`physical_actions_enabled: False` 时状态、RFID 和库存仍可用，但送料、回料、烘干、校准和辅助送料保持禁用。用户完成设备检查并改为 `True` 后，手动送料、回料、烘干和 ACE 内置辅助送料可以独立于自动换料使用。

自动模式只有在必需宏、路径和安全配置通过预检后才允许执行换料。V3 不采用尖端成型，退出旧料必须使用切刀；切刀、送料、回料和故障暂停缺少任一项时，自动换料都不能进入就绪状态。配置不完整属于非致命就绪状态：Klipper 和 ACE 状态读取继续运行，换料按钮、无限续料和自动切刀保持禁用，任何换料事务不得开始。多 ACE 共用打印头时，全局同时只能有一个槽位启用辅助送料。

**辅助送料策略：** 打印中启用必须显式确认，Moonraker 的确认必须继续传递为 Klipper `CONFIRM=1`；停用属于降低风险动作，不要求确认。自动换料装载新槽位前先停用活动辅助送料，停用失败则中止换料，不能并行启动另一台 ACE。

ADR-010 中“六个 `_ACE_MACHINE_*` 宏名固定”的部分由本决策替代；宏仍集中在 `ace.cfg`，名称改为清楚描述动作的七个名称：

- `_ace_prepare_toolchange`
- `_ace_cut_filament`
- `_ace_load_filament_to_toolhead`
- `_ace_unload_filament_from_toolhead`
- `_ace_wipe_nozzle`
- `_ace_restore_after_toolchange`
- `_ace_pause_on_toolchange_error`

所有宏上方必须使用紧凑中文说明，连续写明宏名称、用途、调用时机、可能产生的物理动作、必须检查的项目和默认状态，段内不插入多余空行。换料前处理、切刀、送料、回料、擦嘴、换料后处理和故障暂停七项全部为自动换料必用能力，名称绑定默认全部启用。

`ace.cfg` 在七个宏的名称和绑定注释中统一使用 `!!!【必用】`，醒目表示“缺少该能力时自动换料不可用”。该标记是用户说明，不参与配置解析，也不能替代宏注册与就绪预检；一般风险警告直接写“严重警告”，不得借用 `!!!`，避免与必用状态混淆。

七个名称绑定默认启用只表示驱动固定调用关系，不代表机器相关物理实现已经启用。`_ace_prepare_toolchange`、`_ace_cut_filament`、`_ace_wipe_nozzle` 和 `_ace_restore_after_toolchange` 必须提供以当前 V2 实机流程为蓝本的完整样板，但其 `[gcode_macro ...]` 实现整段默认注释；用户核对本机坐标、方向、速度、归零条件和安全间隙后才能取消注释。任一实现缺失只使自动换料未就绪，不得阻止 Klipper、手动模式或已授权的 ACE 内置辅助送料，也不得通过删除绑定绕过预检。

送料、回料和故障暂停保留完整活动实现。换料前处理、切刀、擦嘴和换料后处理只注释物理实现，不注释 `[ace_machine]` 绑定。本机的 `X289 Y350` 停车位置、`Z2` 抬升、`240` 摄氏度最低温度及切刀坐标只能作为已注释示例，禁止成为通用活动默认值。

送料、回料和故障暂停所需的内部入口必须有完整实现，不得用空宏绕过预检。每个危险宏上方必须直接说明可能造成撞机、撞打印件、误切、堵头或挤出机损坏，并明确禁止照搬示例坐标。配置注释使用普通设备文档语言，不使用 ASCII 字画、星级风险评分、开发过程口吻或重复的抽象警告。

**T 指令策略：** 当自动换料未配置或未就绪时，`T0-T15` 和 `TR` 全部作为安全空操作处理。驱动不得启动换料、调用机器宏、获取路径锁、改变当前工具、修改耗材路径状态、拒绝命令或暂停打印，打印继续执行。每次遇到被忽略的工具指令时，Fluidd 卡片和独立页面都弹出“ACE 自动换料未配置，已忽略工具指令；当前无法进行多色打印，仅可使用已启用的 ACE 内置辅助送料”的提示，不做任务内去重。自动换料完成配置并通过就绪预检后，`T0-T15` 和 `TR` 恢复正常语义。

## ADR-012：多 ACE 使用两级五通和可验证分支清空

**决定：** 单 ACE 使用 1 个总五通，四槽直接汇入总五通，不存在一级五通。只有设备数量达到 2 台时才启用两级 4 进 1 汇流：每台 ACE 使用 1 个一级五通，再共同进入 1 个总五通；2/3/4 台分别需要 3/4/5 个五通。多 ACE 主路径固定为 `ACE 槽位 -> 一级五通 -> 总五通 -> 可选共享编码器 -> 上方传感器 -> 挤出机 -> 喷嘴`；下方传感器不是通用安装必需项，默认旁路并只监测，用户确认其稳定后可显式恢复下方闭环。ACE 内部自行完成张力调节，V3 不得增加独立缓冲器节点，也不得把 ACE 内置缓冲结构解释成 Happy Hare/AFC 所使用的外置缓冲或压缩传感器。

所有用户可配传感器只展示 `*_sensor_pin`。总五通使用 `rdm_sensor_pin`；`ace0_hub_sensor_pin` 至 `ace3_hub_sensor_pin` 只供多 ACE 使用。单 ACE 不创建一级五通对象，即使旧配置残留对应字段也忽略；多 ACE 可以为全部五通安装传感器，也可以只安装总五通传感器。

多 ACE 的每台设备使用 `aceN_hub_retract_length` 与 `aceN_hub_clear_move_length`。前者是总五通释放后寻找本设备一级五通释放的搜索上限，后者是一级五通释放后的停车余量。没有一级传感器时，两段相加作为受限盲回退距离。单 ACE 不读取这两项。

**安全条件：** 多 ACE 自动换料要求每台允许物理动作的 ACE 都有可验证分支清空方案。旧料必须先释放总五通并清空当前一级分支，之后才允许另一台 ACE 送料。一级传感器引脚留空不构成 Klipper 启动错误；存在总五通传感器并完成本设备两段距离校准时可使用盲回退方案，距离也未配置时只将自动换料标记为“尚未就绪”。搜索超限、传感器矛盾或动作结果未知时进入人工检查，不得继续跨设备送料。

**兼容与界面：** 单 ACE 固定显示“ACE -> 总五通 -> 打印头”，不显示一级五通状态。Fluidd 卡片、侧栏页面和静态备用页只有在设备数达到 2 台时才显示“ACE -> 一级五通 -> 总五通 -> 打印头”；总五通状态在设备之间共享，一级五通状态随当前设备切换。

本决策已经冻结；对应配置解析、状态机、模板和前端已通过模拟测试，并部署到单 ACE 目标打印机完成只读状态验证。目标机没有多 ACE 两级硬件，因此多 ACE 真机物理动作验收仍未完成。

## ADR-013：共享编码器只验证运动

**决定：** 首版只支持一个共享编码器，直接安装在总五通之后的公共路径，顺序为 `总五通 -> 编码器 -> 上方传感器 -> 挤出机`。用户配置键为 `encoder_sensor_pin`、`encoder_resolution`、`encoder_detection_length` 和 `encoder_mode`，默认引脚为空、分辨率为 `0`、检测距离为 `20 mm`、模式为 `off`。编码器对象使用驱动固定内部名称；旧 `encoder_sensor_name` 仅作兼容。

**模式：** `off` 不参与动作判断；`monitor` 在 ACE 寻找上方传感器和挤出机接管后的定距段中记录脉冲、测量距离、跟随比例和无进展事件，只提示而不改变动作结果、自动换料就绪、路径状态或重连结论；`protect` 在检测窗口内没有确认实际耗材移动，或跟随比例低于 `encoder_min_tracking_ratio` 时中止当前动作并要求人工检查。该参数默认 `0.6`，有效范围 `0.01..1`。保护模式下编码器不可用或未校准时，自动换料保持未就绪。

**边界：** 编码器只能说明耗材是否实际移动，不能单独说明耗材位于哪一个路径节点，也不能替代总五通、上方或多 ACE 的一级五通开关传感器。下方传感器完全可选；没有下方传感器时，编码器仍可验证挤出机接管后的实际移动，并帮助识别上方传感器与挤出齿轮之间的卡料、未咬料或打滑。检测结果不得触发无上限追加送料、自动打滑补偿或自动恢复。

**校准：** 校准不得驱动 ACE 或挤出机。打印机待机、当前耗材已卸载、共享路径为 `empty` 且辅助送料关闭时，用户执行 `ACE_ENCODER_CALIBRATE START=1` 启动默认 `150 mm x 3` 会话，并在每段手动移动后提交一次 `LENGTH=<实测长度>`。三段一致性和保存规则见 ADR-017；会话期间拒绝新的 ACE 运动、辅助送料启用和自动换料。

**来源：** 脉冲计数、毫米分辨率校准和运动检测机制参考 Happy Hare 固定提交 `73d39aab2110deebb64dfb7899c6838a706edcea`，入口传感器归位、传感器到喷嘴定距及可选工具端传感器的职责划分同时参考 AFC 固定提交 `a06f14dd5b2aa5e2878f92cef7a07f1e8b1fd5a3`。只借鉴设计经验，不复制上游代码，不移植其整套 MMU 拓扑、步进送料机构或外置缓冲器模型。

## ADR-014：打印中连续监测与人工校准向导

**决定：** 打印连续监测与 ACE 送料/回料动作监测使用同一个共享编码器，但采用独立配置。新增 `encoder_print_mode: off|monitor|pause` 和 `encoder_print_detection_length`，默认关闭且阈值为 `20 mm`。未配置编码器、没有计数器采样或无法取得挤出机物理位置时静默停用，不阻止 Klipper 启动和普通打印；只判断新脉冲时不依赖毫米/脉冲分辨率。

**计量：** 监测读取 Klipper 挤出机物理位置并累计净挤出，不依赖切片逻辑 E 坐标。回抽和随后恢复只抵消彼此；打印状态不是 `printing`、路径未装载、存在换料事务或正在校准时不累计。新编码器脉冲重置检测余量，达到阈值无脉冲时每次故障只产生一个事件。

**响应：** `monitor` 记录现场并提示但继续打印，`pause` 额外通过已有错误处理钩子请求一次暂停。故障现场包含工具、设备、路径、打印和传感器状态；可能原因只作排查提示。任何模式都不得自动送料、补偿距离、碰撞归位或把编码器当作有料传感器。打印故障独立于 ACE 动作故障，不改变 `encoder_mode: protect` 的就绪判定。

**校准交互：** Moonraker 提供 `encoder_calibration_start`、`encoder_calibration_finish(length)` 和 `encoder_calibration_cancel` 三个白名单动作，分别映射 `START=1`、`LENGTH=<length>` 和 `CANCEL=1`。它们不接受设备编号、不驱动电机且打印期间全部拒绝。Fluidd 完整页提供可取消的分步人工向导，仪表盘卡片保留状态和故障提示，不把机器动作校准入口一并开放。

## ADR-015：以上方传感器作为 ACE 与挤出机的唯一交接点

**物理前提：** ACE Pro 使用直流电机，不是可由 Klipper 精确累计步数的步进送料机构。耗材材质、线径、卷盘阻力、PTFE 阻力和压轮状态都会改变相同送料时间对应的实际距离。因此发送给 ACE 固件的“距离”只是一项固件参考量或分段请求量，不得显示、记录或判断为耗材已经真实移动的毫米数。

**ACE 送料终点：** ACE 从内部停放点开始送料后，只有上方传感器达到稳定“有料”才算送料成功。`toolchange_load_length`、`feed_slip_compensation_length` 等 ACE 命令距离只能约束单次请求，不能作为成功终点；累计参考距离也不能替代传感器。编码器用于判断送料期间是否仍有实际进展：`monitor` 只提示无进展，`protect` 中止当前送料。`upper_sensor_feed_timeout` 默认 `30` 秒，有效范围 `1..120` 秒；达到该时间仍未稳定触发上方传感器时必须停止，这是传感器故障、空槽、打滑或堵塞情况下的最终硬保护。

**控制权交接：** 上方传感器稳定触发后，驱动立即停止 ACE 前送，把后续控制权交给挤出机步进电机。挤出机按本机重复标定的“上方传感器交接位置到喷嘴目标位置”距离送料；这段距离属于挤出机步进运动，与 ACE 固件参考距离不是同一物理量。`toolhead_sensor_bypass_load_length` 默认样板为 `25 mm`，不能解释为 ACE 已经精确送料 `25 mm`，也不能直接视为本机校准结果。用户实测并低速复核后必须设置 `toolhead_sensor_bypass_calibrated: True`，否则自动换料保持未就绪。

**下方传感器：** 下方传感器不是通用安装必需项。`toolhead_sensor_bypass` 默认 `True`：引脚可留空；即使填写真实引脚，也只持续显示原始状态，不参与装载、卸载、路径就绪、空路径确认或故障原因。用户完成接线、去抖和重复动作验证并确认下方传感器稳定后，可以显式设置 `toolhead_sensor_bypass: False` 恢复下方闭环；此时其触发、释放和相关距离重新参与动作及就绪判定。旧文档中“下方传感器默认必须安装”的规则由本 ADR 明确废止。

**编码器验证：** 编码器应同时覆盖 ACE 寻位段和挤出机接管段。在挤出机已命令送料或回抽、编码器却没有达到合理移动阈值时，可以把故障范围缩小到上方传感器附近、挤出齿轮入口、齿轮未咬料或路径打滑。`monitor` 只记录并提示，不能改变动作结果；`protect` 必须在继续长距离挤出前中止，并且不得把路径标记为已装载。编码器仍不能单独确定耗材绝对位置，上方传感器始终负责交接归位。

**卸载顺序：** 默认旁路模式下，完成切刀动作后由挤出机步进电机受限回抽，直到上方传感器稳定释放；编码器可验证耗材是否真实后退。上方传感器释放后才由 ACE 接管回抽：先释放总五通，再按多 ACE 拓扑释放当前一级五通并执行已校准停车余量。ACE 回抽命令距离仍只是固件参考量，停车结论来自总五通、一级五通或明确配置的受限盲回退方案。用户显式关闭旁路时，下方传感器按恢复后的闭环流程参与装卸阶段。

**上游经验边界：** Happy Hare 展示了“先归位到挤出机入口参考点，再按已校准距离进入喷嘴，并用编码器验证运动”的设计；AFC 展示了只配置入口传感器、工具端传感器可为空时仍使用入口到喷嘴定距的方式。V3 只借鉴这些职责划分。ACE Pro 自带的缓冲结构属于设备内部机构，不能套用为 Happy Hare/AFC 的外置压缩、张力或缓冲传感器，也不能作为 V3 的虚拟归位点。

## ADR-016：GitHub 公开发行默认全新安装

**前提：** 首个 GitHub 公开版本发布时，除项目当前测试机外，没有外部用户安装过 V2 或 V3 预发布版本。公开用户不需要理解旧 `ace_hardware.cfg`、旧 `ace_machine.cfg`、V2 卸载或内部发布迁移过程。

**决定：** README、快速开始和新手教程必须以全新安装为唯一主线。安装器直接生成单文件 `ace.cfg`，公开步骤不得要求用户先寻找、安装、卸载或迁移历史版本。历史迁移只能放在明确标注“普通用户跳过”的维护者章节，不得出现在公开安装检查表中。

**保留能力：** 不删除安装器已有的旧组件检测、非 V3 配置拒绝、拆分配置一次性合并、归档和回滚能力。这些能力继续保护项目当前测试机、内部预发布环境，并防止第三方 ACE 驱动、`T0-T15` 或 `TR` 宏冲突。检测到冲突时仍必须失败关闭，不能因公开用户默认全新安装而静默覆盖未知文件。

## ADR-017：编码器采用三段式校准，运行时保持短窗口

**决定：** 编码器人工校准默认使用 `150 mm` 单段、连续 `3` 段。每段独立保存脉冲数、测量长度和 `mm/脉冲`，不得只累计成一个总数后计算。段间一致性使用三个分辨率结果的最大相对偏差判断：`<=5%` 直接通过；`>5%` 且 `<=10%` 显示警告，只有用户明确确认后才能保存；`>10%` 拒绝保存。任一段脉冲不足、长度无效、前置状态变化或计数异常时，本轮校准失败且不得覆盖上一次有效结果。

**边界：** `150 mm` 是兼顾常见 15 cm 测量工具与分段重复性的校准长度，不是运行时打滑检测距离。ACE 寻位和挤出机接管继续使用 `encoder_detection_length` 的短窗口，打印连续监测继续使用 `encoder_print_detection_length` 的短窗口。不得为减少误报把运行时窗口改成 `150 mm`，否则会显著延迟卡料、未咬料或打滑响应。

**未校准门禁：** `encoder_resolution: 0`、未完成全部三段、偏差未确认或校准结果无效时，编码器保护不得 armed。`monitor` 可以用于只读观察原始脉冲，但不得把未校准数据解释为可靠距离。

## ADR-018：安装器保留持久快照并输出可执行恢复信息

**决定：** 正式安装、升级、重装、增删设备和 Fluidd 源码集成在第一次写入前创建独立、时间戳化的持久快照。快照覆盖本次可能修改的 Klipper、Moonraker、Fluidd、ACE 配置、托管块、链接、安装清单和必要元数据，并记录来源路径、文件类型、校验值和创建原因。

安装事务内部仍使用临时备份完成失败自动回滚，但临时事务目录不能代替持久快照。安装成功后不得删除持久快照；安装器必须在最终输出中给出快照路径、恢复命令、恢复范围和校验结果。恢复操作默认只恢复该次安装实际管理的内容，不静默删除快照之外的用户文件。

Fluidd 源码模式的完成条件固定为：兼容性与锚点检查、应用补丁、使用目标 Fluidd 自身声明的 Node 与包管理器构建、部署生成的 `dist`、验证 Dashboard 卡片与 `#/acepro` 路由。只完成补丁不属于部署完成；构建或部署失败时保留 `/ace-v3/` 备用页，并提供快照恢复路径。
