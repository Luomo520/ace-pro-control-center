# Ace Pro Control Center | ACE Pro 管理中心：第三代实施计划

## 2026-08-04 实施状态

批次 0-6 已形成正式版本 `V2.5ahpha`；配置协议仍为第三代 `driver_version: 3`。2026-08-03 有界整体审查完成打印安全、安装配置保留、前端确认/RPC/陈旧状态和 ACE2 长时帧边界修复；随后完成单 ACE 工具按钮过滤、四列对齐、Klipper E 坐标同步、动作前挤出安全检查、单 ACE 单级路径和硬件模板排版。2026-08-04 发布 `20260804_005657` 完成 `ace.cfg` 单文件配置迁移，并通过 Klipper、Moonraker、ACE1 只读状态、Fluidd 页面、事务回滚点和前后备份验收。

安装器兼容收口已经完成：Klipper 改用源码 API 与实际 Python 环境能力探测，Fluidd 改用版本范围、依赖和源码锚点联合判断；不兼容的 Fluidd 在 `auto` 模式回退独立页面，`source` 模式在写入前失败。官方 Klipper `v0.10.0-v0.13.0` 与当前上游、Fluidd `1.34.4-1.37.3` 均已进入真实源码验证矩阵。

真机前安全复核已收口：串口 I/O 已移出 Reactor 主线程，非幂等动作禁用自动重发，手动送料/回抽纳入共享路径状态机，恢复动作要求路径协调，无续料候选时暂停失败不再被吞掉，机器钩子和挤出条件在 ACE 动作前预检。手动模式、七宏命名和新安装安全默认值已经部署；此后不追加无边界代码审查，只按明确需求和实测结果修复可复现问题。

以下批次按依赖顺序执行。每批次完成后先通过本地门槛，再进入下一批次；不向打印机部署未完成批次。

## 真机验收前补充：手动模式与机器宏配置重构

- 在 `[ace]` 增加 `toolchange_mode: manual|automatic`，全新安装默认 `manual`；配置不完整不得阻止 Klipper 启动。
- 把换料“已启用”和“已就绪”分开建模并输出到 Klipper/Moonraker 状态；手动模式在 Fluidd 卡片和独立页面使用中性提示，自动换料相关按钮保持禁用。
- 全新 ACE1 默认 `physical_actions_enabled: False`；升级、重装和增删设备时保留已有安全开关，不得把已验证的 `True` 改回默认值。
- 手动模式在物理动作门禁开启后支持手动送料、手动回料、烘干和单槽 ACE 内置辅助送料；多 ACE 共用路径时全局只能激活一个辅助送料槽。
- 将旧六个 `_ACE_MACHINE_*` 宏迁移为七个清晰名称，并为 `[ace_machine]` 增加独立擦嘴钩子。V3 不采用尖端成型；换料前处理、切刀、送料、回料、擦嘴、换料后处理和故障暂停全部为必用，七个绑定默认启用。前处理、切刀、擦嘴和后处理保留完整但整段注释的 V2 实机样板，用户核对本机动作后才能取消注释；绑定启用不得被解释为物理实现已启用。
- 在 `ace.cfg` 的七个宏名称和绑定注释中统一添加 `!!!【必用】`；一般风险警告不使用该标记。标记只改善用户识别，自动换料可用性仍由实际预检决定，缺失实现不得阻止 Klipper、手动模式或已授权的 ACE 内置辅助送料。
- 从新模板和填写说明中移除所有 `*_sensor_name`，用户只填写 `*_sensor_pin`；空 pin 禁用传感器，有值时由驱动以固定内部名称创建对象。旧显式 name 只保留解析与迁移兼容。
- 重写 `ace.cfg` 宏区说明：每个宏上方紧凑写明用途、时机、物理动作、必检项和默认状态；删除 ASCII 字画、星级风险评分和重复抽象措辞。
- 同步修改配置解析、Manager 能力门禁、Klipper 命令、Moonraker API、两套前端、安装器、升级器、发布校验和测试，确保不存在新旧宏名混用。
- 自动换料未配置或未就绪时，将 `T0-T15` 和 `TR` 实现为无状态变更、无物理动作、不拒绝且不暂停打印的安全空操作；每条工具指令都发送结构化提示供两套前端弹窗，不做任务内去重，自动换料就绪后恢复正常语义。
- 完成条件：全新未配置安装可正常启动并停留手动模式；自动模式未就绪时不产生物理动作；重装保留用户值；七宏迁移和单辅助送料的后端、前端及安装集成测试全部通过。

## 已完成补充批次：单文件配置迁移

- `config/ace.cfg` 已成为唯一活动模板，并按“安装器托管硬件拓扑 -> 共享参数 -> 机器钩子 -> 机器宏”排列；活动 `[include ace_hardware.cfg]` 已删除。
- 安装器全新安装只生成 `ace.cfg`，`printer.cfg` 的 ACE 相关配置只保留 `[include ace.cfg]`；不再创建新的 `ace_hardware.cfg` 或 `ace_machine.cfg`。
- 升级器只读取一次旧 `ace_hardware.cfg`，将设备身份、通信参数和安全开关合并进 `ace.cfg`，成功后以不覆盖历史的名称归档到配置目录的 `.ace-driver-v3/legacy/`。归档文件不会再次 include，也不会在后续重装时反向覆盖当前配置。
- 旧 `ace_machine.cfg` 继续只作为一次性迁移输入；机器宏、校准值和适用自定义 G-code 合并进 `ace.cfg` 后退出运行链。
- 安装器只管理硬件拓扑块的结构、设备数量、逻辑顺序和通信身份；已有的 `enabled`、`rfid_enabled` 和 `physical_actions_enabled` 按稳定硬件身份保留。共享路径参数、编码器校准、机器宏、用户尾部内容和未知扩展项不受硬件重排影响。
- 增删 ACE、替换型号或改变 ACE1/ACE2 组合仍通过重新运行安装器完成；手工复制活动设备节不属于受支持的拓扑修改方式。
- 安装、升级、重复安装、事务回滚、卸载、发布清单和配置契约测试已经覆盖单文件布局；失败回滚恢复 `ace.cfg`、`printer.cfg` include 和旧文件位置。
- 本地和目标打印机完成条件均已满足：发布树中不存在活动 `ace_hardware.cfg`，运行时只加载 `ace.cfg`；旧硬件文件已归档到 `.ace-driver-v3/legacy/`。迁移完成前后备份、打印状态检查、服务重启、配置预检、ACE1 在线状态和回滚点校验均已通过。
