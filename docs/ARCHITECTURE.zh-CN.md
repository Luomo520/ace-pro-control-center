# Ace Pro Control Center | ACE Pro 管理中心：第三代架构

## 1. 总体分层

```text
Fluidd / Moonraker / KlipperScreen
              |
        V3 状态与动作 API
              |
      AceManager（全局编排）
              |
 AceInstance（每台设备四槽）
              |
  Protocol Adapter（ACE1 / ACE2）
              |
 Reactor 协作等待 / 串口工作线程
              |
 Transport（独立串口或 ACE2 共享总线）
```

核心依赖方向只能从上到下。界面和 Moonraker 不得直接写串口；协议层不得调用打印头坐标或厂家宏。

配置边界与运行关系固定为：`printer.cfg -> ace.cfg`。`printer.cfg` 只 include `ace.cfg`；`ace.cfg` 是唯一活动 ACE 配置，同时保存 `[ace_hardware]`、`[ace_device ace0..ace3]`、运行模式、单级或两级五通路径、多 ACE 分支距离、可选共享编码器、`[ace_machine]` 钩子映射以及七个机器动作宏。运行时不得继续 include `ace_hardware.cfg` 或 `ace_machine.cfg`。

## 2. 需要保留的 `Kobra-S1/ACEPRO` 内容

- `AceManager` 与 `AceInstance` 的职责划分。
- ACE1、ACE2 独立协议适配器。
- 串口占用、超时、重连和连接状态监督。
- 每设备独立库存、干燥状态、错误状态和能力集合。
- 全局工具映射、无限续料和持久化状态的抽象。
- 协议、工具映射、库存、重试和启动校验测试。

对应来源文件：

- `extras/ace/manager.py`：全局实例编排和工具注册思路。
- `extras/ace/instance.py`：单设备四槽动作和状态边界。
- `extras/ace/serial_manager.py`：串口生命周期、重连和端口隔离。
- `extras/ace/protocol.py`：协议名称、传输能力和公共类型。
- `extras/ace/ace2_bus.py`：ACE2 共享总线和 UID 绑定。
- `extras/ace/persistent_state.py`、`endless_spool.py`、`runout_monitor.py`：按批次接入的可选能力。

这些文件提供设计和测试参考，不要求原样保留 Kobra 专属分支。

## 3. 需要从 SV08 保留或核对的内容

- ACE1 JSON 帧封装、CRC、请求 ID 和响应匹配。
- `get_status`、`get_info`、干燥、送丝、回抽、助推的 ACE1 动作语义。
- 加载、卸载和换料的顺序及必要等待。
- SV08 四行界面和按钮语义。

协议帧不能由 Manager 或前端重新实现；所有上游动作必须经过 `Ace1Protocol`。

对应 SV08 文件：

- `extras/ace.py`：ACE1 JSON 帧和基础动作流程。
- `ace.cfg`：动作宏的调用顺序和 SV08 用户操作语义，仅作参考。
- `PROTOCOL.md`：协议字段和帧格式的交叉验证来源。

SV08 的配置文件不能直接作为通用设备配置安装。

## 4. 必须剔除的内容

- `Kobra-S1/ACEPRO` 的 Kobra S1/K3/K3M 专用配置文件和打印机宏。
- SV08 的固定引脚、固定传感器 pin、固定坐标、固定切刀和停靠动作。
- 通过描述字符串寻找“第一个 ACE”作为连接身份。
- 未经通用 Klipper API 证明的特殊 Klipper、KlipperScreen 或厂家对象。
- ACE2 尚未真机验证的物理动作默认值。

## 5. 机器动作适配层

驱动只定义可选钩子，并由 `ace.cfg` 实际实现：

- `_ace_prepare_toolchange`
- `_ace_cut_filament`
- `_ace_load_filament_to_toolhead`
- `_ace_unload_filament_from_toolhead`
- `_ace_wipe_nozzle`
- `_ace_restore_after_toolchange`
- `_ace_pause_on_toolchange_error`

七宏结构与 `[ace_machine]` 名称映射都位于 `ace.cfg`。V3 不使用尖端成型，换料前处理、切刀、送料、回料、擦嘴、换料后处理和故障暂停全部是自动换料必用能力；七个名称绑定默认启用并统一标记 `!!!【必用】`。换料前处理、切刀、擦嘴和换料后处理的机器动作实现仍是整段注释的 V2 样板，名称绑定不会启用样板坐标。用户完成本机校准前不得取消这些实现的注释；缺少任一实现时自动换料保持未就绪，但 Klipper、手动模式和已授权的 ACE 内置辅助送料继续可用。LOAD/UNLOAD 只进入 Python 路径控制器，普通 Jinja 宏不承担实时传感器循环。Klipper 的 `ace_machine.py` 仍作为 `[ace_machine]` section 的被动加载器保留，但这不意味着需要或允许继续加载同名的 `ace_machine.cfg` 文件。

### 5.1 配置迁移

新安装只创建当前 `ace.cfg`，不创建 `ace_hardware.cfg` 或 `ace_machine.cfg`。重新安装或升级时，安装器使用合并升级流程：先移除 `ace.cfg` 中指向旧拆分文件的 include，再分别读取旧 `ace_hardware.cfg` 和旧 `ace_machine.cfg`。硬件文件中的设备身份、通信参数和设备安全开关合并到 `ace.cfg` 的安装器托管拓扑块；机器文件中的宏、校准变量和自定义 section 合并到当前七宏结构。装载/卸载两个进入 Python 路径控制器的桥接宏使用新版安全模板覆盖；旧宏名称和内部引用迁移到七个新名称。

迁移时，七个名称绑定统一保持启用；停车、切刀、擦嘴和恢复的物理实现优先保留旧文件中的校准内容和注释状态；送料、回料和错误处理保持活动实现。合并成功后，旧 `ace_hardware.cfg` 归档到配置目录的 `.ace-driver-v3/legacy/`，旧 `ace_machine.cfg` 也退出运行时 include；所有归档只用于追溯和恢复，不得再次由 Klipper 加载。

硬件拓扑块的结构、设备数量、逻辑顺序和通信身份由安装器管理。重新安装、增删设备或改变 ACE1/ACE2 组合时，安装器按串口稳定路径或 ACE2 总线与 UID 识别同一物理设备，保留该身份对应的 `enabled`、`rfid_enabled` 和 `physical_actions_enabled`，不得按临时枚举顺序串位。运行时所有硬件拓扑、共享参数和机器动作配置都共同归属 `ace.cfg`。

## 6. 两级五通物理拓扑

单 ACE 的四槽直接进入总五通，不使用一级五通。设备数达到 2 台后，每台 ACE 的四槽先进入本设备一级五通，再进入共享总五通。4 台拓扑如下：

```text
ACE0 四槽 -> 一级五通 0 --\
ACE1 四槽 -> 一级五通 1 ---\
ACE2 四槽 -> 一级五通 2 ----> 总五通 -> 可选共享编码器 -> 上方传感器 -> 挤出机 -> 喷嘴
                                                                           └-> 可选下方传感器（默认监测，可选闭环）
ACE3 四槽 -> 一级五通 3 ---/
```

单 ACE 只需要 1 个总五通。2/3/4 台分别需要 2/3/4 个一级五通和 1 个总五通，总数为 3/4/5 个。单 ACE 运行时不实例化一级分支；多 ACE 只实例化实际配置的设备分支。

总五通沿用 `rdm_sensor_pin`。`ace0..ace3` 的一级五通字段只供多 ACE 使用；单 ACE 不创建一级传感器对象，即使旧配置残留 pin 也忽略。多 ACE 可以全部安装传感器，也可以只在总五通安装传感器。

多 ACE 的每个分支独立保存 `aceN_hub_retract_length` 与 `aceN_hub_clear_move_length`；单 ACE 不读取这些字段。距离属于物理分支，不能在设备之间默认复制。

单 ACE 路径状态不包含一级五通；多 ACE 才区分当前设备一级五通、共享总五通和打印头路径，并逐台验证分支清空方案。

两级五通配置解析、分支状态机和当前设备路径展示已完成模拟测试，并随当前候选部署到单 ACE 目标打印机完成只读验证。目标打印机没有多 ACE 两级硬件，因此跨设备送料、回抽和分支清空仍未完成真机物理动作验收。

### 6.1 上方传感器交接与挤出机接管

ACE Pro 的直流电机不能提供可信的步数位置。ACE 送料请求中的距离只供设备固件参考；耗材摩擦、卷盘阻力和压轮状态会改变相同请求对应的真实位移。路径控制器必须把 ACE 阶段实现为寻位状态机：以受限请求送料，以上方传感器稳定触发为唯一成功终点，以编码器判断是否仍有实际进展，并用 `upper_sensor_feed_timeout` 作为最终硬停止；默认 `30` 秒，有效范围 `1..120` 秒。达到命令参考距离、累计参考距离或编码器测得某个距离都不能代替上方传感器宣告到位。

上方传感器触发后立即停止 ACE，并把控制权交给挤出机步进电机。挤出机按 `toolhead_sensor_bypass_load_length` 运动，默认样板 `25 mm`，必须按本机标定；共享编码器存在时同时验证耗材是否真实跟随。`encoder_min_tracking_ratio` 默认 `0.6`，有效范围 `0.01..1`；`monitor` 只生成提示，`protect` 在无进展或比例不足时中止并禁止把路径标记为已装载。下方传感器不是通用必装项：`toolhead_sensor_bypass` 默认 `True` 时 pin 可为空，已接线也仅公开原始状态；用户确认稳定后可显式设为 `False` 恢复下方闭环。

默认旁路模式的卸载采用相反交接顺序：切刀完成后，挤出机受限回抽到上方传感器稳定释放，再由 ACE 接管并依据总五通、当前一级五通或已校准受限盲回退方案停车。显式关闭旁路时，下方传感器恢复参与闭环装卸。ACE 回抽距离同样只是固件参考量。任何交接未确认、时间超限或 `protect` 无进展故障都使路径保持未知并进入人工检查。

### 6.2 共享编码器

系统只允许一个共享编码器，直接安装在总五通之后、上方传感器之前的公共路径，使所有 ACE 分支经过同一测量点。ACE 设备内部自行完成张力调节，不属于 V3 的外部拓扑或配置。编码器对象由 Klipper `pulse_counter` 提供脉冲累计；V3 保存毫米/脉冲分辨率、ACE 动作检测和打印连续检测两套独立模式、阈值及最近结果。

`off` 不建立动作判断，`monitor` 在 ACE 寻位段和挤出机接管段记录脉冲和跟随比例但不改变动作结果，`protect` 在检测窗口内没有确认实际运动时中止当前动作、把路径置为未知并要求人工检查。保护模式只有在编码器可用且分辨率已校准时才处于 armed 状态；否则自动换料保持未就绪。编码器不判断绝对位置，不替代总五通、一级五通或上方传感器，也不命令 ACE 无上限自动补料；下方传感器不是必须由编码器替代的节点，而是独立的可选只读信号。

打印连续监测通过 Klipper 挤出机物理位置计算净挤出量，不依赖可能被 `G92 E0` 重置的切片逻辑 E 值。回抽先形成负债，随后等量恢复只抵消负债；只有继续向前的净挤出才消耗检测余量。监测仅在 `print_stats=printing`、工具已装载、路径无事务且不在校准时活动。`monitor` 生成一次事件但继续打印，`pause` 生成事件后经机器错误钩子请求一次暂停。新脉冲重置余量，故障状态不得触发自动补料、距离补偿或自动恢复。

校准是无电机动作的三段人工流程：`ACE_ENCODER_CALIBRATE START=1` 默认启动 `3` 段、每段 `150 mm` 的会话；用户每完成一段手动移动就提交一次 `ACE_ENCODER_CALIBRATE LENGTH=<实测长度>`。每段独立记录脉冲和 `mm/脉冲`；最大偏差 `<=5%` 通过，`>5%` 且 `<=10%` 警告后允许保存，`>10%` 或任一段脉冲不足拒绝保存。`LENGTH` 只接受 `0.01..2000 mm` 的有限数值；`CANCEL=1` 可退出。整个会话要求打印机待机、耗材已卸载、路径为 `empty` 且辅助送料关闭，并拒绝新的自动换料和 ACE 运动。

该机制参考 Happy Hare GPLv3 项目固定提交 `73d39aab2110deebb64dfb7899c6838a706edcea` 的编码器、入口归位和入口到喷嘴定距设计，并参考 AFC 固定提交 `a06f14dd5b2aa5e2878f92cef7a07f1e8b1fd5a3` 中入口传感器可独立于工具端传感器工作的职责划分。只借鉴设计经验，不复制代码，不引入 selector、gear stepper、MMU toolhead、自动补偿、Spoolman、MMU 恢复或外置缓冲器逻辑。ACE 内置缓冲结构始终属于设备内部，不进入 V3 传感器拓扑。

## 7. 全局事务

`AceManager` 负责：

- 创建 1-4 台设备实例并校验配置。
- 将 `Tn` 映射到设备和本地槽位。
- 维护全局当前工具和共享路径锁。
- 串行化跨设备换料、回抽、送丝和无限续料。
- 聚合连接、能力、库存和错误状态。
- 统一处理打印状态门禁和未知结果。
- 在切断旧料前检查目标槽；单 ACE 使用上方和总五通，多 ACE 再加入当前设备一级五通决定停放位置。旁路为 `True` 时下方只保留原始状态；显式设为 `False` 时恢复闭环事务结论。
- 将 ACE 寻找上方传感器、挤出机接管、挤出机回抽至上方释放和 ACE 清空五通路径串行协调，保持一条共享路径只有一个动作所有者。
- 保持物理事务锁直到送料或回抽完成并重新确认 ready。
- 跨设备送料前，先确认旧料已释放总五通，再使用当前分支传感器或受限盲回退清空一级分支；任一阶段未确认时禁止启动目标 ACE。
- 对 ACE 寻位和挤出机接管运动分别创建共享编码器测量窗口；`monitor` 只记录，`protect` 故障时中止并保持路径未知，禁止无上限自动追加运动。
- 在打印活动期间按净挤出更新共享编码器余量；无新脉冲达到阈值时记录独立打印故障，按 `monitor/pause` 策略提示或请求一次暂停。

pyserial 的读取、超时和重连运行在专用工作线程；Klipper Reactor 只做协作等待，不得被离线设备的串口超时阻塞。只读查询可以按配置重试，送料、回抽、助推、烘干和 ACE2 地址分配等非幂等命令只发送一次。响应丢失时进入物理状态未知，不猜测动作是否执行。

换料开始前必须一次性验证所有必需机器钩子已经配置且对应宏已注册。预检失败不得先向 ACE 发送部分送料或回抽动作。

单台 `AceInstance` 只负责本设备四槽和本设备协议动作，不决定全局当前工具。

## 8. 状态与动作 API

状态至少包含设备、库存、动作能力、共享总五通、打印头路径和共享编码器；只有多 ACE 状态才包含当前设备一级五通及分支清空数据。

动作 API 至少包含：查询状态、刷新、换料、卸载、送丝、回抽、设置槽位、开始/停止烘干、启停无限续料，以及编码器校准开始、完成和取消。校准动作不接受设备编号、不驱动电机且打印期间拒绝。每个动作必须返回明确的成功、失败、拒绝原因和是否可重试。

状态查询只能读取缓存，不因刷新界面而同步执行物理动作。

## 9. 前端架构

V3 同时交付 Fluidd 卡片和 Moonraker 独立控制界面。两者共用框架无关的状态校验、ViewModel、能力判断、动作客户端和错误模型。

Fluidd 卡片以 V2 单设备管理中心为基础。单 ACE 显示“ACE -> 总五通 -> 打印头”；多 ACE 增加设备切换并显示“ACE -> 一级五通 -> 总五通 -> 打印头”。

所有动作通过 `POST /server/ace/action` 发送结构化请求。Moonraker 负责白名单、参数、打印状态、确认和能力校验；任何前端都不得直接执行原始 G-code。
