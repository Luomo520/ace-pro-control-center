# ACE Pro 管理中心项目记忆

更新时间：2026-07-29
当前工作区版本：`1.2.0`
用途：作为对话压缩、任务交接和多智能体协作时的单一事实入口。详细实现仍以代码、测试和专项文档为准。

## 1. 产品定义

- 中文名：ACE Pro 管理中心。
- 英文名：Ace Pro Control Center。
- 来源：从 `szkrisz/ACEPROSV08` 衍生的独立 GPL-3.0 项目。
- 用户：使用一台 ACE Pro 的 DIY Klipper 打印机用户。
- 当前范围：单设备、T0-T3 四料槽、Klipper 驱动、Moonraker 受控 API、Fluidd 原生卡片和备用 `/ace.html`。
- 非目标：多台 ACE、替代 Fluidd 的独立网站、自动兼容或卸载其他 ACE 驱动、未经确认的机械动作。

运行时兼容标识必须保留：`[ace]`、`ACE_*`、`/server/ace/*`、`ace.py`、`ace.cfg`。新身份为 `ACE_PRO_CONTROL_CENTER`，兼容读取旧身份 `ACEPROSV08`。

## 2. 产品原则

1. Fluidd 卡片是主入口；备用页与卡片功能应一致，只允许尺寸和布局不同。
2. 前端不能执行任意 G-code，所有动作经 Moonraker 白名单和参数校验。
3. 物理传感器优先于保存状态；状态冲突时停止，不猜测耗材位置。
4. USB 断联后不得盲目重放未确认的送料、回抽、切刀或换料动作。
5. 安装、更新、回滚和卸载都必须可恢复，不覆盖历史归档。
6. 默认宏不得归零、移动、加热或执行切刀；机器专属动作由用户明确配置。
7. 项目尽量通过第三方驱动、Moonraker 组件和 Fluidd 模块集成，避免修改 Klipper、Moonraker 和 Fluidd 上游核心，以保留正常升级能力。

## 3. 系统边界

| 层 | 主要路径 | 职责 |
| --- | --- | --- |
| Klipper 驱动 | `extras/ace.py`、`ace.cfg` | 串口、槽位、传感器、换料、烘干、探测和恢复 |
| Moonraker | `ace_status_integration/moonraker/ace_status.py` | 状态归一化、能力发现、命令白名单和 API |
| Fluidd | `fluidd-source-overlay/`、`fluidd-dist/` | 原生导航页、仪表盘卡片和用户操作 |
| 备用页 | `ace_status_integration/web/` | 与卡片同能力的备用控制和诊断入口 |
| 安装器 | `install.sh`、`ui-installer.sh`、`uninstall.sh` | 安装、版本提示、归档、回滚、卸载和状态检查 |

完整功能清单见 `docs/FEATURES.zh-CN.md`，开发流程见 `docs/DEVELOPMENT.zh-CN.md`，决策依据见 `docs/DECISIONS.zh-CN.md`，安装行为见 `docs/INSTALL.zh-CN.md`，驱动参数见 `docs/DRIVER-v1.2.0.zh-CN.md`。

## 5. 当前工作区状态

- 工作区基于 `v1.2.0` 后续开发，提交前必须确认差异仅包含当前工作单；不得用清理命令覆盖用户修改。
- `ace.cfg` 去锁修复已加入本地安装器：保留旧软链接真实内容，转换成普通可写文件，并保持回滚/卸载恢复能力。
- 安装器已改为复制并验证归档后再替换目标，加入统一事务恢复、全局首次写入前基线、源码/运行目录重合拒绝、Moonraker 版本风险和配置模式校验；五组安装器测试和 GitHub Actions 原生 Linux 真实软链接验证均已通过。
- Fluidd API 已改为失败关闭：404、网络错误、409 和 5xx 都不会回退发送原始 G-code；生产构建已同步。
- 换卷命令现要求 `CONFIRM=1`，Fluidd、备用页、Moonraker 和驱动契约一致；不确定切刀/回抽不会自动重放。
- 当前业务回归已通过：Python 149 项、Web 29 项、Fluidd 340 项、类型检查、lint、生产构建和五组安装器事务测试；清单逐项校验通过。
- 上一版 160/120 mm/s、100 mm 粗测已完成真机静态验证；当前版本改为送料/回抽 50 mm/s、主体和末段分段 50 mm，已写入打印机。
- 当前生产构建包含 259 个文件和 198 个资源，只有一组 ACE JS/CSS chunk；首页与 Service Worker 引用完整，本轮 Windows 构建已通过，尚未进行 Ubuntu 逐文件可复现构建。
- 送料失败后的历史错误不再作为永久活动警告；自动探测会明确显示状态过期、打印/暂停、换料恢复、动作锁、ACE busy、传感器不可用或仍有料等阻塞原因。无活动动作时可清除软件故障提示，物理位置不会被改写。
- `manifest.sha256` 必须在本轮所有代码、文档和生产构建完成后重新生成并校验；继续排除 `.git/`、`.temporary/`、`.playwright-cli/`、旧 Release 附件、`__pycache__/`、`*.pyc` 和 `*.pyo`。
- GitHub 仓库已更名为 `Luomo520/ace-pro-control-center`，旧地址可重定向；本轮代码已推送远端 `main`，未连接或修改打印机。
- 真机当前运行状态必须在每次任务开始时重新查询，不得把历史“ready”状态当作当前事实。
- `ACE_CONFIG_SPECIFICATION.zh-CN.md` 是配置契约规范；根目录 `ace.cfg` 是唯一可安装模板和发布值来源，`docs/templates/ace-config-section.template.ini` 只供后续编写参数和功能区，不得安装或扩写成第二套配置。规范不固定活动参数数量，也不复制当前机器值；机械必填项统一使用 `☆☆☆☆☆`。
- 材料名称、烘干温度和推荐打印温度最终保留在 `[ace]` 内并三项成组；历史 `[ace_materials]` 建议已作废。配置或派生状态对外暴露时，必须同步 Moonraker、Fluidd、备用页、文档和测试。
- `ace_config_version`、`extruder_sensor_debounce_count`、
  `toolhead_sensor_debounce_count`、`toolchange_feed_hard_limit` 和
  `toolchange_retract_hard_limit` 已从保留需求转为正式实现。旧配置缺失新键时按兼容
  路径加载；硬上限失败停止换料并暂停正在打印的任务，不执行 `CANCEL_PRINT`。
- `sensor_trigger_grace_time` 已加入驱动和唯一配置模板，理论送料时间结束后默认继续
  监测 3 秒；宽限期不追加移动距离，失败诊断会记录理论时间、宽限时间、最终状态和
  连续有效样本数。Fluidd 命令业务错误不再显示为 API 断联。
- 本轮对上述五项只确认静态部署层：配置解析、服务、API 和状态；未执行送料、回抽、
  切刀、自动探测或完整换料，不得把静态结果描述为物理验证通过。

## 6. 未关闭风险

- 安装事务、首次基线和混合安装顺序 P0 已完成五组安装器测试；`driver/card/all` 混合顺序卸载可恢复全局首次写入前基线，原生 Linux 真实软链接类型和目标恢复验证通过，P0-001 已关闭。
- Fluidd 失败关闭和驱动物理动作安全 P0 已完成本地自动测试，尚未进行真机运行时验证。
- 非 Fluidd `v1.37.2` 或非 Moonraker `v0.9.3` 只提供风险提示和可回滚安装，不代表完整兼容。
- Windows Git Bash 不一定创建真实符号链接，因此发布流程继续保留 GitHub Actions 原生 Linux 软链接测试。
- 自动测试不能替代切刀坐标、传感器电平、送料打滑、管路长度和 USB 稳定性的真机验证。
- 卡片、备用页、Moonraker 和驱动能力可能随并行修改产生漂移，发布前必须执行跨层功能矩阵审计。
- 构建目录存在旧哈希资源删除和新哈希资源新增；发布前必须确认 `index.html`、Service Worker 和实际资源完全一致。

当前优先级和关闭条件见 `docs/PRODUCT_BACKLOG.zh-CN.md`；证据见 `docs/audits/` 三份领域审计。

## 7. 工作流与质量门槛

1. 产品负责人创建工作单并冻结目标、非目标和验收标准。
2. 子智能体按驱动、Moonraker/Fluidd、安装恢复、测试文档分工，写入范围不得重叠。
3. 本地集成后执行语法、单元测试、接口测试、构建、安装器事务和清单验证。
4. 涉及打印机时严格执行变更前备份、空闲检查、部署、静态验证、服务状态验证和变更后备份。
5. 物理动作测试必须由用户在现场明确触发。
6. 只有用户明确要求时才提交或发布 GitHub，并在发布前再次审计许可证、文档、版本和清单。
