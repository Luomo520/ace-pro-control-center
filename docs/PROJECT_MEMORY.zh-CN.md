# Ace Pro Control Center | ACE Pro 管理中心：第三代项目记忆

## 当前冻结结论

- 项目面向通用 Klipper 设备。
- 第一次 GitHub 公开发行时，除项目当前测试机外没有用户安装过 V2 或 V3 预发布版本。公开教程、快速开始和默认安装体验必须以全新安装为主线，不得要求普通用户先卸载 V2 或理解旧拆分配置；历史冲突检测和迁移能力仅用于维护者测试机、内部预发布环境及防止第三方 ACE 驱动冲突。
- 代码地基采用 `Kobra-S1/ACEPRO` 的模块化多设备结构。
- `szkrisz/ACEPROSV08` 仅作为 ACE1 协议、动作语义和 Fluidd 四行布局基线。
- 不复制任何 Kobra S1/K3、SV08 专属引脚、坐标、MCU、传感器 pin 或厂家宏。
- 最多 4 台 ACE 对一个打印头，工具固定为 `T0-T15`；设备按配置顺序映射，断线或 USB 重枚举不得改变工具号。
- 单 ACE 固定使用单级路径：四槽直接进入 1 个总五通，不安装、不配置也不显示一级五通。只有设备数量达到 2 台时才启用两级汇流；2/3/4 台 ACE 分别使用 2/3/4 个一级五通，再共同进入 1 个总五通，总数分别为 3/4/5 个。多 ACE 主路径为 `ACE 槽位 -> 一级五通 -> 总五通 -> 可选共享编码器 -> 上方传感器 -> 挤出机 -> 喷嘴`；下方传感器只作可选观测。ACE 内部自行完成张力调节，V3 不得增加独立缓冲器节点，也不得套用 Happy Hare/AFC 的外置缓冲传感器模型。
- `printer.cfg` 运行时只 include `ace.cfg`。`ace.cfg` 是唯一活动 ACE 配置：安装器托管的硬件拓扑、设备身份与能力开关，以及运行模式、共享路径、传感器、速度、安全策略、耗材类型、`[ace_machine]` 配置节和机器宏都在此文件中。
- 旧 `ace_hardware.cfg` 仅作为安装器一次性迁移输入；合并后归档到配置目录的 `.ace-driver-v3/legacy/`，不再 include。硬件拓扑块由安装器管理，重装时按稳定硬件身份保留 `enabled`、`rfid_enabled` 和 `physical_actions_enabled`。
- 旧 `config/ace_machine.cfg` 仅作为旧安装迁移输入，不参与运行时 include；安装器不再创建它。旧宏与校准值迁入 `ace.cfg` 后，归档文件仅用于追溯和恢复。
- 七个机器宏固定为：`_ace_prepare_toolchange`、`_ace_cut_filament`、`_ace_load_filament_to_toolhead`、`_ace_unload_filament_from_toolhead`、`_ace_wipe_nozzle`、`_ace_restore_after_toolchange`、`_ace_pause_on_toolchange_error`。核心、模板、安装器、升级器和测试已经统一使用该契约；旧六宏只允许存在于 legacy 迁移输入中。
- V3 不采用尖端成型。换料前处理、切刀、送料、回料、擦嘴、换料后处理和故障暂停共七项全部为自动换料必用能力，名称绑定默认全部启用。
- ACE1 是当前唯一具备真机验收条件的型号；ACE2 首版只读，物理动作强制关闭。
- V2 Fluidd 卡片和独立控制界面纳入 V3 正式范围；保留功能和交互经验，改用多设备状态与结构化动作 API。
- Fluidd 原生工具命令区保留驱动固定注册 `T0-T15` 的后端契约，但界面只按 `ace.device_count` 显示已安装设备的通道：每台 ACE 独占一行四列，1 台只显示 `T0-T3`，2/3/4 台分别显示 8/12/16 个工具按钮；ACE 状态缺失或无效时保持 Fluidd 原始行为。
- 用户配置只展示各传感器的 `*_sensor_pin`：有值时驱动以固定内部名称创建对象，留空表示禁用。总五通继续使用兼容前缀 `rdm_sensor_*`；一级五通字段只供 2 至 4 台 ACE 使用，单 ACE 即使旧配置残留 `ace0_hub_*` 也必须忽略。旧显式 `*_sensor_name` 只作为升级兼容输入，不再出现在新模板和填写说明中。
- ACE Pro 使用直流送料电机，命令距离只能作为固件参考量，不能代表真实耗材位置。ACE 送料以上方传感器稳定触发为唯一成功终点；`upper_sensor_feed_timeout` 默认 `30` 秒、范围 `1..120` 秒，负责最终硬停止。上方触发后停止 ACE，由挤出机步进电机按本机标定距离接管。
- 下方传感器不是通用安装必需项。`toolhead_sensor_bypass` 默认 `True`，已接线也仅监测；用户确认稳定后可显式设为 `False` 恢复下方闭环。`toolhead_sensor_bypass_load_length` 默认 `25 mm`，表示默认旁路模式下挤出机控制的入口到喷嘴标定距离，不是 ACE 送料距离。
- 首版编码器只有一个，直接位于总五通之后的公共路径。用户配置键为 `encoder_sensor_pin/resolution/detection_length/mode`，默认 `off`；编码器在 ACE 寻位段和挤出机接管段验证耗材是否真实移动，不替代上方或五通传感器，也不自动补料。`monitor` 只提示，`protect` 中止当前阶段。

## 当前配置与运行要求

- 全新安装默认 `toolchange_mode: manual`。缺少停车、切刀、擦嘴、传感器或路径配置时，Klipper 和 ACE 状态读取仍正常运行，自动换料只显示为未启用或尚未就绪，不显示为设备故障，也不开始任何换料动作。
- `toolchange_mode` 与设备级 `physical_actions_enabled` 分离。全新 ACE1 默认 `physical_actions_enabled: False`；升级或重装按稳定硬件身份保留 `enabled`、RFID 和物理动作开关的已有值，设备换序不能串位，新设备不能继承旧设备授权。
- 手动模式在设备物理门禁开启后，允许独立使用手动送料、手动回料、烘干和 ACE 内置辅助送料，不要求配置完整自动换料。单打印头全局同时只能有一个辅助送料槽位。
- 自动模式必须先通过机器宏和共享路径预检；配置不完整不是 Klipper 启动错误，只关闭自动换料、无限续料和自动切刀能力。
- 旧“下方传感器默认闭环、开启旁路后才允许入口到喷嘴定距”的契约已经废止。入口到喷嘴距离仍必须由挤出机低速重复标定，`0` 表示未标定并只关闭自动换料；`250 mm` 仅为防止误填的解析硬上限，不是建议距离。默认旁路模式下，下方传感器的存在、缺失和跳变不改变换料结论；新流程仍需真机动作验收。
- 仅多 ACE 的每台动作型设备独立配置 `aceN_hub_retract_length` 与 `aceN_hub_clear_move_length`。存在一级传感器时分别表示“总五通释放后寻找一级五通释放的搜索上限”和“一级五通释放后的停车余量”；不存在一级传感器时两段合并为总五通释放后的受限盲回退。单 ACE 不读取这些字段。
- 多 ACE 自动换料要求总五通有效，并且每台动作型 ACE 都有可验证分支清空方案。支持 5 个五通全部带传感器，也支持仅总五通带传感器；一级传感器 pin 留空且距离未校准时 Klipper 仍须启动，但自动换料保持“尚未就绪”。旧料清空当前分支和总五通后，另一设备才能送料。
- 共享编码器的 ACE 动作监测使用 `encoder_mode: off/monitor/protect`；`monitor` 只读取和记录，不得改变动作结果、换料就绪、`current_tool`、`path_state` 或重连结论，重连只清除观察故障；只有 `protect` 故障可以中止动作并要求路径恢复。打印连续监测独立使用 `encoder_print_mode: off/monitor/pause`，默认均关闭。打印监测阈值默认 `20 mm`，只累计打印中的净挤出，回抽与恢复不累计；每次故障只记录一个事件，`pause` 经错误处理宏请求一次暂停，不自动补料。
- 编码器校准固定采用三段式人工测量：默认每段 `150 mm`、默认 `3` 段，每段独立记录脉冲数和 `mm/脉冲`。段间最大偏差 `<=5%` 直接通过，`>5%` 且 `<=10%` 必须警告并取得明确确认后才允许保存，`>10%`、任一段脉冲不足或数据无效时拒绝保存。校准过程不驱动 ACE 或挤出机，打印中拒绝开始、提交和取消；Fluidd 完整页提供可取消的逐段向导及实时计数。`150 mm` 只用于校准，运行时打滑检测继续使用短窗口，不得把校准段长写入 `encoder_detection_length` 或 `encoder_print_detection_length`。
- 宏不得留空。七个名称绑定默认全部启用；换料前处理、切刀、擦嘴和换料后处理的机器动作实现保持完整注释样板，用户核对本机坐标、方向、速度、归零条件和安全间隙后才能取消注释。绑定启用只建立调用契约，不表示物理实现已启用。
- 送料、回料和故障暂停保留完整活动实现。七项能力缺少任一项时自动换料未就绪，但不得阻止 Klipper、手动模式或已授权的 ACE 内置辅助送料，也不得通过删除绑定绕过预检。
- `ace.cfg` 的七个宏名称和绑定注释全部使用 `!!!【必用】`；该标记只作醒目说明，不代替代码预检，也不用于一般风险警告。
- 每个宏上方使用紧凑中文说明，连续写明宏名称、定位、用途、调用时机、物理动作、必须检查和默认状态；段内不留多余空行。危险宏必须直接说明机械风险，示例坐标禁止照搬。
- 每个宏上方的操作说明不使用 ASCII 字画、星级风险评分、开发过程口吻或重复抽象措辞，使用普通设备说明语言并保持紧凑。
- ACE 未配置、自动换料未配置或未就绪时，只允许只读管理和已经授权的 ACE 内置辅助送料，不得把手动送料、回料或其他换料动作误称为可用。`T0-T15` 和 `TR` 全部忽略并继续打印，不调用宏、不获取路径锁、不改变当前工具或路径状态，不拒绝也不暂停。每条工具指令都必须发送中文提示：“ACE 自动换料未配置，已忽略 Tn。当前无法进行多色打印，仅可使用已启用的 ACE 内置辅助送料。”其中 `Tn` 使用本次实际指令，不做任务内去重；通过自动换料就绪预检后恢复正常工具语义。
- `toolhead_sensor_bypass_load_length: 25` 仅是未校准样板。新安装必须以独立校准状态标记其无效，不能仅凭数值非零判定已校准；用户完成本机重复测量并确认保存前，自动换料保持未就绪。运行时不得把该值解释为 ACE 精确送料距离。
- 安装器正式写入前必须创建时间戳持久快照，覆盖本次将修改的 Klipper、Moonraker、Fluidd、ACE 配置、托管块、链接和清单。安装失败使用事务回滚；安装成功后快照仍保留，并输出快照路径、恢复命令、恢复范围和校验结果。临时事务目录不能代替持久恢复点。
- Fluidd 源码模式必须完成“能力检查 -> 补丁 -> 使用目标版本自身 Node/包管理器构建 -> 部署 `dist` -> 路由与卡片验证”。只完成源码补丁不得宣称原生界面已经部署；构建失败必须保留 `/ace-v3/` 备用页和明确恢复路径。

## 版本状态

- 正式版本名：`V2.5ahpha`；内部配置协议继续使用 `driver_version: 3`。包含单文件配置迁移、两级五通、共享编码器、编码器打印监测、校准向导和单 ACE 单级路径修正的发布 `20260804_005657` 已部署到目标打印机。
- 目标打印机是单 ACE `single_device`，只显示 `T0-T3`，不创建、不读取也不显示一级五通；两级五通配置字段和分支状态机已完成本地模拟，多 ACE 物理路径仍待具备相应硬件后验收。
- 单文件配置契约已在本地源码和目标打印机实现：硬件拓扑由安装器写入 `ace.cfg` 的托管区域，运行时不再 include 独立 `ace_hardware.cfg`；旧文件只在升级时读取一次，成功合并后归档到 `.ace-driver-v3/legacy/`。目标打印机当前运行链固定为 `printer.cfg -> ace.cfg`。
- 驱动代码：已完成配置、模型、ACE1/ACE2 协议、串口工作线程、Reactor 协作等待、设备实例、全局 Manager、安全门禁、持久化、无限续料、G-code 和 Klipper 生命周期入口。
- ACE2：已实现配置 UID、发现、地址分配和定向只读轮询；未绑定 UID 保持离线；物理动作仍由协议层和管理层双重拒绝。
- Moonraker：已完成状态、能力和结构化动作 API；前端不得回退到任意 G-code。
- 前端：已完成共享核心、V2 风格 Fluidd 管理卡片和多 ACE 切换；Fluidd 提供 Dashboard 卡片与 `#/acepro` 侧栏页面，`/ace-v3/` 保留为静态备用页。单 ACE 只显示总五通路径，多 ACE 才显示当前一级五通；共享编码器始终是全局状态。
- 新的传感器控制契约已经在当前本地源码、配置模板、前端和自动化测试中实现：ACE 以上方传感器作为唯一交接点并受送料超时保护；挤出机负责交接点到喷嘴的标定距离；下方传感器默认仅监测、可选恢复闭环；多 ACE 回抽依靠总五通、当前一级五通或受限盲回退。本轮改动尚未上传打印机，该新流程及多 ACE 两级路径均尚未完成真机动作验收。
- 送料安全状态机按受限窗口反复请求 ACE：主参考量和低速参考量耗尽后仍继续低速寻找上方传感器，但总时间绝不超过 `upper_sensor_feed_timeout`。固件提前返回完成时仍等待传感器宽限，截止时间后的迟到触发固定为失败，读取传感器异常必须补发停止。路径只有在上方明确为无料、所有已配置五通信号明确清空时才能判为 `empty`；旁路下方允许保持只读或缺失。
- 编码器 ACE 段每个窗口都排除零脉冲，避免短动作和长动作中途卡死被静默放过；跟随比例只用于挤出机步进段。`protect` 下挤出机保证运动距离短于 `encoder_detection_length` 时必须在物理动作前拒绝，G-code 边界使用普通命令错误返回，不得触发 Klipper 内部关机。
- 挤出安全：`_ace_prepare_toolchange` 运行后、任何 ACE 物理动作前检查活动挤出机 `can_extrude` 和每次移动的 `max_extrude_only_distance`；驱动直接移动 E 轴后同步 Klipper 的 G-code E 基准，保持调用前的 `M82/M83` 模式和逻辑 E 坐标。
- 配置迁移：`merged` 模式负责移除旧 `ace_machine.cfg` 与 `ace_hardware.cfg` include；硬件区域更新器一次性读取旧硬件文件，按稳定身份保留设备开关并写入 `ace.cfg` 托管区域，随后使用不覆盖历史的文件名归档旧文件。机器宏、用户校准和配置尾部自定义内容继续由共享配置升级器保留。
- 手动模式、自动换料就绪门禁、七宏命名、安全注释样板、固定 `T0-T15/TR`、逐条工具提示、全局单槽辅助送料、动态工具区、挤出安全、单 ACE 单级路径和单文件配置迁移均包含在当前发布 `20260804_005657` 中。
- 自动换料就绪检查要求设备物理动作已启用、七个必用宏均已注册、上方传感器可读取、入口到喷嘴距离已标定、`upper_sensor_feed_timeout` 有效且路径可恢复。旁路为 `True` 时下方不是就绪条件；显式设为 `False` 时下方闭环必须有效。`encoder_mode: protect` 时还要求编码器可用、已校准、`encoder_min_tracking_ratio`（默认 `0.6`、范围 `0.01..1`）有效，且挤出机保证运动距离不得短于 `encoder_detection_length`。
- 辅助送料独立于自动换料：启用受 `physical_actions_enabled` 和显式确认约束，打印中最终 Klipper 命令必须带 `CONFIRM=1`；停用无需确认并可随时释放当前槽位。自动换料装载前先停用活动辅助送料，停用失败时不启动新槽位。
- 工具提示前端已统一通知游标：首次加载消费当前队列，Klipper 序号重置后第一条通知不会遗漏，Fluidd 使用单 snackbar 顺序展示。
- 安装器：已完成重复安装、旧 V3 配置契约升级、用户校准与设备安全开关保留、`SAVE_CONFIG` 前置 include、dry-run、卸载、冲突回滚、旧 V2 检测、活动 `TR/T0..T15` 宏冲突检查和 Klipper 配置节 wrapper；`ace_encoder.py` 已纳入安装、更新、卸载、回滚和发布校验清单。硬件清单生成器已经改为 `ace.cfg` 内托管区域更新器，并完成旧 `ace_hardware.cfg` 的一次性迁移、归档、严格后置预检和双源冲突拒绝。
- Klipper 兼容：通过实际源码 API、Klipper Python 和 pyserial 能力探测决定安装；已验证上游 `v0.10.0`、`v0.11.0`、`v0.12.0`、`v0.13.0` 与提交 `d865997`，并通过 Python `3.8.10` 全项目编译检查。
- Fluidd 兼容：官方 `1.34.x-1.37.x` 由 manifest profile 管理；`auto` 不兼容时回退 `/ace-v3/`，`source` 写入前失败，`standalone` 不修改源码。真实源码验证版本为 `1.34.4`、`1.35.1`、`1.36.4`、`1.37.3`。
- 切片器兼容：V3 不接管 `PRINT_START` 的温度参数。目标打印机的 `PRINT_START EXTRUDER=... BED=...` 参数名已与实际宏核对一致，实际切片中的 `T[initial_tool]` 已展开为 `T0`。工具行写在 `PRINT_START` 之后时会在整个开始宏完成后执行；手动/未就绪模式逐次提示并忽略，自动且就绪时才进入换料事务。
