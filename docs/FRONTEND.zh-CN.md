# Ace Pro Control Center | ACE Pro 管理中心：前端规范

## 1. 产品组成

V3 同时提供两种 Fluidd 入口和一个静态备用入口：

1. **Fluidd ACE 卡片**：仪表盘中的日常状态与高频操作入口。
2. **Fluidd ACE 侧栏页面**：`#/acepro` 中的完整控制、库存、维护、诊断和恢复入口；通用机器动作校准保持禁用，共享编码器提供独立人工向导。
3. **静态备用界面**：`/ace-v3/`，在无法重建 Fluidd 源码时仍可使用。

三者必须使用同一状态模型、能力模型、错误模型和动作 API，不得分别实现换料策略。

两级五通与共享编码器状态展示已完成模拟测试，并部署到单 ACE 目标打印机完成页面和只读状态验证；多 ACE 路径与编码器物理动作仍未完成真机验收。共享编码器属于同一共享路径模型，不得按设备复制。

## 3. Fluidd 卡片

卡片保持 V2 单设备管理中心的信息层级：

1. 顶部：控制面板标题、V2 副标题和当前设备连接状态；仪表盘菜单只保留“打开页面”。
2. 设备状态：型号、运行状态、设备温度、风扇转速、RFID、当前装载、总五通、共享编码器、作为交接依据的上方传感器、可选只读下方传感器和无限续料；一级五通只在 2 至 4 台 ACE 时显示。
3. 烘干控制：目标温度、时长、当前状态、目标温度、剩余时间和启停动作。
4. 四槽管理：每槽显示全局 `Tn`、卷料图、硬件状态、SKU、材料、温度、颜色、换料、保存和清空；保持四槽紧凑并排。
5. 手动送料：料槽、长度、速度、送料和回抽保持同一行的 V2 顺序。
6. 快捷操作：刷新状态、卸载当前耗材、批量保存当前设备未保存的库存草稿、诊断传感器和无限续料。
7. 校准和恢复：保留在侧栏完整页面的维护区域，不占用仪表盘卡片的 V2 主操作层级。

多设备不同时可见。配置两台及以上时，在标题下显示 `ACE 1..ACE 4` 切换按钮；按钮按实际设备数等宽显示对应全局工具范围。所有设备的槽位编辑组件保持挂载，因此切换设备不会丢弃未保存草稿；所有可见槽位和动作仍只绑定当前选中设备。单设备时隐藏切换按钮，并且不得额外插入 V2 截图不存在的全宽实时状态条。卡片提供进入 Fluidd 侧栏页面的按钮。

Fluidd 原生“工具”命令区必须读取 Klipper `ace.device_count`，只显示实际安装设备拥有的工具号。每台 ACE 固定为一行四列：1 台显示 `T0-T3`，2 台增加 `T4-T7`，依次扩展到 4 台的 `T0-T15`。按钮宽度等分，短行不得拉伸或错列。驱动仍固定注册 `T0-T15` 以保证切片文件和配置重装兼容；界面过滤不改变后端命令契约。ACE 状态对象缺失、格式错误或设备数超出 `1..4` 时，不猜测设备数量，改用 Fluidd 原始工具分组。

RFID 显示服从每台设备的 `rfid_enabled`。显式关闭时设备与槽位均显示“已关闭”；默认开启时，协议值 `0`（无资料）和 `1`（识别失败）也按“已关闭”展示，避免把未放置或不带标签的卷料表现为持续故障。协议值 `2` 显示“已识别”，值 `3` 显示“识别中”；未收到任何字段时显示“未提供”。关闭 RFID 不得清空或弱化手工库存的材料、颜色和温度显示。

单 ACE 路径固定显示“ACE -> 总五通 -> 打印头”，一级五通项目完全隐藏。2 至 4 台 ACE 时改为“ACE -> 一级五通 -> 总五通 -> 打印头”，一级五通随设备切换，总五通和打印头路径保持全局共享。未安装一级传感器时显示“未配置”，不得用推测值显示有料或无料。

下方传感器原始读数来自 `path.sensors.lower`。默认 `toolhead_sensor_bypass: True` 时标为“仅监测 · 有料/无料/未配置”；用户显式设为 `False` 时标为“参与控制 · 有料/无料/未配置”，并显示对应就绪或故障原因。界面不能把下方传感器表现为通用必装项。

共享编码器位于 `path.encoders.shared`，设备切换时保持同一状态。界面分别显示 ACE 寻位、挤出机接管和打印监测的策略与最近结果，至少区分“未配置、未校准、校准中、关闭、监测、保护、暂停策略、故障”；无脉冲不得直接显示为“无料”。编码器只提供运动信息，界面不得提示它能够替代上方/五通传感器或自动补料；挤出机段无进展可提示“可能未进入挤出齿轮或发生打滑”，但不能自动断言具体故障。

槽位点击语义：

- 点击未装载且可用槽位：请求换入对应 `Tn`。
- 点击当前已装载槽位：请求卸载，必须二次确认。
- 点击离线、空槽、只读或被安全门禁的槽位：不发送动作，显示阻塞原因。
- 手动模式或自动换料未就绪时：换料和无限续料入口禁用，但手动送料、回料、烘干、库存和辅助送料仍按各自能力显示。
- 启用 ACE 内置辅助送料必须确认设备与槽位，打印中允许启用；停用不要求确认。整个单打印头拓扑只能有一个活动辅助送料槽位。

## 4. 独立控制界面

Fluidd 侧栏页面复用同一卡片并默认展开维护和诊断区域。静态备用页面使用相同共享核心和 API，但不依赖 Fluidd 组件。

独立界面至少包含：

- 系统总览：打印状态、全局当前工具、共享路径锁、共享总五通、共享编码器、打印头路径和活动事务；当前设备一级五通只在多 ACE 时出现。
- 设备视图：1-4 台 ACE 的连接、协议、固件、温度、烘干和四槽状态。
- 工具与库存：`T0-T15`、材料、颜色、温度、RFID 来源和手动覆盖。
- 换料控制：选择工具、卸载当前工具、换卷。
- 维护动作：手动送丝、手动回抽、冷态预装载和完全卸载。
- 烘干控制：单机或多机目标、温度、时长、自动跟随打印策略。
- 无限续料：启停、匹配方式、候选槽位和跨设备选择结果。它属于单打印头共享耗材路径的全局设置，不随当前界面选中的 ACE 改变；在任一设备页面修改后，所有设备页面必须立即显示同一状态。
- 校准：通用机器动作校准继续保持禁用；共享编码器提供“开始 -> 手动推动并填写实测长度 -> 完成”的分步向导和随时可用的取消按钮。开始前必须说明向导不会自动送丝，打印中禁用全部校准动作。
- 诊断与恢复：连接、传感器、槽位、错误、恢复要求和下一步建议。编码器打印故障显示发生时间、工具、设备、路径状态、打印状态、传感器快照和仅供参考的可能原因。

独立界面不提供任意 G-code 输入框，不允许绕过能力接口执行物理命令。

## 5. API 契约

读取接口：

- `GET /server/ace/status`
- `GET /server/ace/capabilities`

动作接口：

- `POST /server/ace/action`

动作请求使用固定结构：

```json
{
  "action": "select_tool",
  "params": { "tool": "T5" },
  "confirm": true,
  "client": "fluidd-card"
}
```

Moonraker 必须重新校验设备、工具、打印状态、能力、共享路径锁和确认令牌。前端不得发送原始串口协议，也不得在 API 失败时回退到 G-code。

编码器向导使用固定白名单动作 `encoder_calibration_start`、`encoder_calibration_finish` 和 `encoder_calibration_cancel`。只有完成动作携带 `0.01..2000 mm` 范围内的有限 `length`；三者均不发送 `device`。开始和完成按钮必须服从“无已装载工具、路径为 `empty`、辅助送料关闭”的后端能力门禁；取消用于安全退出校准状态，不表示校准成功。

## 6. 共享前端核心

Fluidd 卡片与独立界面共用以下逻辑：

- 状态和能力响应校验。
- `aceN + slot 0..3 -> Tn` 映射。
- 按设备数量切换的单级/两级五通、共享编码器和打印头路径 ViewModel。
- 设备、槽位、烘干、事务和错误 ViewModel。
- 动作可用性与阻塞原因。
- 结构化动作请求和错误处理。
- 中文显示文本和可扩展本地化键。

框架适配层只负责 Fluidd Vue 组件或独立页面挂载，不得复制领域逻辑。

## 7. 必须剔除的前端内容

- 固定 `toolhead: S1` 或把槽位标签写成含义不清的 `S1..S4`。
- 单设备四槽数组作为整个系统唯一库存。
- V2 的 `TOOL=-1..3` 范围限制。
- 直接构造 `ACE_*` G-code 字符串。
- Moonraker 不可用时调用 Klipper 控制台接口作为回退。
- 把 ACE2 在线误认为物理动作已经通过验证。

界面显示本地“槽1..槽4”，内部使用索引 `0..3`，全局操作始终使用 `T0..T15`。

## 8. 用户体验和安全

- 所有长动作显示等待、进行中、成功、失败和恢复建议。
- 同一事务期间禁用冲突动作，但状态刷新保持可用。
- 危险动作必须显示设备、工具、材料、预计动作和确认原因。
- 打印期间只开放打印流程明确允许的操作。
- 页面刷新或网络重连不得重复提交上一动作。
- 首次连接只建立工具提示序号游标，不重放历史提示；之后按 `sequence` 逐条展示每个被忽略的 `T0-T15/TR`，不得合并连续提示。
- Fluidd 卡片与独立界面对同一状态显示一致，不产生两个当前工具。
- 多 ACE 设备切换只替换一级分支状态；单 ACE 不得生成一级分支状态。共享总五通和打印头路径不得因切换设备而被重置。
- 共享编码器的模式、校准和故障状态不得随设备切换重置；`protect` 未就绪时应显示自动换料的明确阻塞原因。
- 打印监测故障按 `event_sequence` 每个事件只弹出一次；页面刷新可继续显示最近故障现场，但不得重放旧弹窗或重复提交暂停。可能原因必须使用“可能”措辞，不得伪装成确定诊断。
- 手机与桌面布局不得出现槽位错列、文字覆盖或控件重叠。
