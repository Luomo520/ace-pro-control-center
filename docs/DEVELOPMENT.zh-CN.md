# Ace Pro Control Center | ACE Pro 管理中心：第三代开发规范

本文档定义 V3 的实现顺序、模块边界、配置契约和验证规则。V3 面向通用 Klipper 设备，最多支持 4 台 ACE 共用一个打印头，工具编号固定为 `T0-T15`。4 台 16 路的标准物理拓扑为两级 4 进 1 汇流，共使用 4 个一级五通和 1 个总五通；可选共享编码器直接安装在总五通之后的公共路径。ACE 内部自行完成张力调节，V3 不得提供独立缓冲器节点、参数或用户界面。

## 1. 开发顺序

1. 固定并记录 `Kobra-S1/ACEPRO`、`ACEPROSV08` 与 `Happy-Hare` 上游版本、许可证和来源。
2. 提取协议和动作行为，建立独立 ACE1 模拟测试。
3. 建立通用 `Transport`、`Protocol`、`AceInstance`、`AceManager`，先完成单 ACE1。
4. 完成多 ACE 编排、稳定工具映射、两级五通分支清空、库存和路径锁，再接入前端状态。
5. 加入 ACE2 只读适配器和协议层、管理层双重物理动作门禁。
6. 完成 V2 风格 Fluidd 卡片、独立控制页面和多设备切换。
7. 完成配置迁移、安装器、打包和卸载；本地测试通过后才准备真机部署。
8. 真机部署前执行变更前备份；部署后验证服务、配置加载和只读状态，再按风险顺序验收物理动作。

不得先以界面按钮代替后端能力，也不得把尚未在目标设备验证的物理动作写成已支持。

## 2. 代码与配置边界

核心 Python 代码只能依赖通用 Klipper API、Python 标准库和已声明的串口依赖。每个设备实例必须独立拥有串口对象、请求 ID、读写队列、定时器、连接状态和库存缓存。

协议层负责帧编码、解码、CRC、请求匹配、协议错误和能力声明。设备层负责单台设备的四槽状态与动作。管理层负责全局工具、路径锁、打印门禁、换料事务和跨设备协调。前端只消费结构化状态和能力，不直接拼接底层 G-code。

V3 的活动配置边界固定如下：

- `config/ace.cfg`：唯一活动配置。文件内部包含安装器托管的设备拓扑和能力清单，以及用户可调的运行模式、共享路径、总五通、多 ACE 专用一级五通与分支距离、可选共享编码器、速度、安全策略、耗材候选、`[ace_machine]` 配置节和七个机器适配宏。
- 旧 `ace_hardware.cfg`：仅用于升级时的一次性迁移输入。安装器合并设备数量、`ace0..ace3`、型号、稳定串口、ACE2 总线、UID 和设备安全开关后，将原文件归档到配置目录的 `.ace-driver-v3/legacy/`；不得继续 include。
- 旧 `config/ace_machine.cfg`：仅用于从旧安装迁移，不是运行时配置；新安装器不得创建或 include。旧宏与校准值合并进 `ace.cfg` 后退出运行链，归档不得被 Klipper 加载。

机器适配仍是通用驱动之外的边界，但宏的存放位置统一在 `ace.cfg`。目标宏名固定为：

- `_ace_prepare_toolchange`
- `_ace_cut_filament`
- `_ace_load_filament_to_toolhead`
- `_ace_unload_filament_from_toolhead`
- `_ace_wipe_nozzle`
- `_ace_restore_after_toolchange`
- `_ace_pause_on_toolchange_error`

宏体虽然位于 `ace.cfg`，职责仍属于本机适配层：坐标、温度、清洁和停车动作必须由用户按本机校准；Python 路径控制器负责传感器实时循环、挤出机分段运动和 ACE 协同。通用核心不得猜测坐标、温度、引脚或打印机运动。旧 `_ACE_MACHINE_*` 名称必须通过安装器迁移到新名称，不能与新名称同时注册。

`toolchange_mode` 与 `physical_actions_enabled` 是两个不同门禁：

- `toolchange_mode: manual` 是全新安装默认值。机器宏、路径传感器或换料距离未配置时仍允许 Klipper 启动、ACE 连接和只读状态更新，自动换料能力显示为未启用，不显示为设备故障。
- `toolchange_mode: automatic` 只有在机器宏和共享路径预检通过后才允许开始换料；预检失败只关闭换料能力，不得先执行任何部分动作。
- 全新 ACE1 默认 `physical_actions_enabled: False`；升级和重装保留用户已有值。该值为 `False` 时，送料、回料、烘干、校准和辅助送料全部禁止。
- 手动模式下把设备门禁改为 `True` 后，可以单独使用手动送料、手动回料、烘干和 ACE 内置辅助送料，不要求先启用自动换料。全局同时只能有一个槽位启用辅助送料。
- 打印中启用辅助送料必须显式确认；Moonraker 接受结构化确认后必须把 `CONFIRM=1` 传入最终 Klipper 命令，直接 G-code 不得隐式确认。
- 自动换料装载新耗材前必须先停用当前辅助送料；停用失败时换料失败关闭，不能让两台 ACE 同时向共享路径送料。

### 2.1 两级五通与分支清空

单 ACE 的四槽直接进入 1 个总五通，不需要一级五通。只有设备数达到 2 台时才启用两级汇流；多 ACE 路径为：

```text
ACE 槽位 -> 一级五通 -> 总五通 -> 可选共享编码器 -> 上方传感器 -> 挤出机 -> 喷嘴
                                                                  └-> 可选下方传感器（只读观测）
```

2/3/4 台 ACE 分别使用 2/3/4 个一级五通和 1 个总五通，总数为 3/4/5 个。单 ACE 固定使用单级路径，运行时不得创建、读取或显示一级五通对象；旧配置残留的 `ace0_hub_*` 必须忽略。

上方、下方、总五通、多 ACE 的一级五通和共享编码器只展示 `*_sensor_pin`。总五通使用 `rdm_sensor_pin`；`aceN_hub_sensor_pin` 只供 2 至 4 台 ACE 使用。单 ACE 所有一级引脚保持为空且不创建 Klipper 对象；多 ACE 的一级传感器仍可选。

多 ACE 的每台设备支持以下分支距离，单位均为毫米；单 ACE 不读取：

- `aceN_hub_retract_length`：总五通释放后，寻找本设备一级五通释放的最大回抽距离；没有一级传感器时作为第一段受限盲回退。
- `aceN_hub_clear_move_length`：一级五通释放后的停车余量；没有一级传感器时与上一段相加，形成总五通释放后的受限盲回退总量。

多 ACE 自动换料只对具备可验证分支清空方案的动作型设备开放。有效方案为“总五通传感器 + 本设备一级五通传感器 + 已校准搜索上限和停车余量”，或“总五通传感器 + 本设备两段已校准盲回退距离”。一级传感器 pin 留空代表该传感器不存在，不得造成 Klipper 启动错误；没有一级传感器时改用距离方案，距离也未完成时将自动换料标记为“尚未就绪”。

跨设备换料必须保持同一全局事务锁：旧料先退出打印头路径并释放总五通，再清空当前设备的一级分支；只有两项均确认完成后，另一设备才允许送料。传感器矛盾、搜索超过上限、盲回退距离缺失或动作结果未知时，路径进入人工检查状态，不得继续向其他分支送料。

两级五通配置解析、分支状态机和三级路径界面已完成模拟测试，并部署到单 ACE 目标打印机完成只读状态验证；目标机没有多 ACE 两级硬件，因此真机送料、回抽和跨设备换料仍未验收。

### 2.2 ACE 寻位、挤出机接管与可选下方传感器

ACE Pro 的送料电机是直流电机。相同命令在不同耗材、卷盘阻力、压轮压力和 PTFE 阻力下对应的实际位移不同，因此实现不得把 ACE 命令距离或累计参考距离当作耗材位置。ACE 阶段是“寻找上方传感器”的寻位过程：

1. ACE 以约两秒的受限窗口分段送料；请求中的距离只供 ACE 固件参考。主参考量和低速参考量耗尽后仍使用低速窗口继续寻找交接点，直至上方触发或总超时。
2. 上方传感器稳定触发是唯一成功终点，触发后立即停止 ACE 前送。
3. 编码器存在时检查耗材是否仍有实际进展；`monitor` 只提示，`protect` 在无进展检测窗口到达时中止。
4. `upper_sensor_feed_timeout` 是最终硬保护，默认 `30` 秒，有效范围 `1..120` 秒。达到时间仍未触发上方传感器时必须停止，不得因编码器仍有脉冲而无限延长，也不得仅根据“已命令多少毫米”宣告成功。

上方传感器稳定触发后，控制权交给挤出机步进电机。挤出机按本机标定的“上方传感器交接位置到喷嘴目标位置”距离送料；`25 mm` 只能是待修改样板，不是通用值。若兼容期继续使用 `toolhead_sensor_bypass_load_length` 这一旧键名，它只表示挤出机控制段的标定距离，不能用来描述 ACE 的真实送料距离。编码器在这一段验证耗材是否随挤出机实际移动，可帮助识别耗材卡在上方传感器附近、未进入挤出齿轮或齿轮打滑。

下方传感器不是通用安装必需项。`toolhead_sensor_bypass` 默认 `True`：`toolhead_sensor_pin` 可留空；填写引脚后继续创建对象和显示原始状态，但不参与装载、卸载、路径就绪、空路径确认或故障原因。用户确认下方传感器在实际耗材和完整装卸中稳定后，可显式设置 `toolhead_sensor_bypass: False` 恢复下方闭环；此时必须配置有效引脚、搜索距离和到喷嘴距离，其触发与释放重新参与动作及就绪判定。

默认旁路模式下，卸载先由挤出机受限回抽，直到上方传感器稳定释放；编码器可验证真实回退。随后由 ACE 回抽并依次确认总五通、当前一级五通或受限盲回退停车方案。显式关闭旁路时，下方传感器恢复参与对应装卸阶段。所有阶段必须有有限搜索、时间或事务上限，失败后保持路径未知并要求人工检查。

### 2.3 共享编码器

首版只支持一个共享编码器，直接位于总五通之后的公共路径，顺序固定为 `总五通 -> 编码器 -> 上方传感器 -> 挤出机`。它由 Klipper 脉冲计数器采样，按 `encoder_resolution` 将脉冲换算为毫米，并分别验证 ACE 寻找上方传感器期间和挤出机接管后的实际耗材运动。ACE 的每个受限窗口都必须排除零脉冲，长窗口还要求至少两个有效脉冲，避免开头移动后中途卡死仍被整段判为正常；命令距离仍不能解释为真实位移。挤出机阶段可将步进命令距离与编码器实测位移作合理阈值比较，`protect` 必须在动作前拒绝短于 `encoder_detection_length` 的保证距离。

ACE 动作的用户配置键为 `encoder_sensor_pin`、`encoder_resolution`、`encoder_detection_length` 和 `encoder_mode`。驱动使用固定内部对象名，旧 `encoder_sensor_name` 只作兼容。打印连续监测另用 `encoder_print_mode` 与 `encoder_print_detection_length`，默认分别为 `off` 和 `20`。两种模式互不覆盖；未配置编码器时打印监测静默不可用，不得阻止 Klipper 启动或普通打印。

`encoder_min_tracking_ratio` 默认 `0.6`，有效范围 `0.01..1`，表示运动验证允许的最低跟随比例。`encoder_mode: monitor` 是只读观察策略：允许读取脉冲、位移、跟随比例和故障记录，但不得改变送料或回料结果、自动换料就绪、路径所有权、`current_tool`、`path_state` 或重连判定。`ACE_RECONNECT` 可以清除该观察故障；只有 `protect` 故障可以中止动作、把路径置为未知并触发恢复流程。

编码器只验证运动，不单独判断耗材绝对位置，不替代总五通、多 ACE 的一级五通或上方开关传感器，也不触发无上限追加送料或距离补偿。下方开关传感器不是必要条件；没有它时，编码器与上方传感器共同提供“交接点已到达”和“耗材确实在移动”两类互补信息。

校准必须在打印机待机、当前耗材已卸载、共享路径为 `empty` 且辅助送料关闭时由用户手工完成：`START=1` 默认启动 `150 mm x 3` 会话，每段移动后提交一次 `LENGTH=<实测长度>`。Fluidd 卡片必须复用同一后端动作；校准期间每次有效正脉冲增量都通过 Klipper `respond_info()` 输出本次新增、本段累计和硬件累计，完成或取消后停止。三段分别记录脉冲和 `mm/脉冲`，按 `5%/10%` 阈值通过、警告或拒绝；脉冲不足、长度无效或偏差过大不得覆盖上一次有效分辨率。`LENGTH` 接受 `0.01..2000 mm` 有限数值；`CANCEL=1` 可退出。会话不得驱动 ACE 或挤出机，并拒绝新的 ACE 运动、辅助送料启用和自动换料。

打印监测必须优先通过 `extruder.find_past_position()` 和 MCU estimated print time 读取物理位置。算法按净挤出累计，回抽和等量恢复不增加累计值；仅在打印中、路径已装载、无换料事务且非校准状态运行。达到阈值无新脉冲时每次故障只递增一次事件序号。`monitor` 只记录，`pause` 通过现有 `pause_on_error` 机器钩子请求一次暂停。打印故障与 ACE 动作故障分开保存，不能改变 `encoder_mode: protect` 的 armed 判定。

## 3. 可保留、可修改、必须剔除

### 保留

- `Kobra-S1/ACEPRO` 的模块化分层、ACE2 总线抽象、连接监督、库存持久化和测试组织。
- SV08 的 ACE1 帧行为、送丝/回抽/换料顺序和四行界面布局经验。
- V2 的卡片、独立控制页面、库存、烘干、维护、换料和错误反馈交互经验。

### 修改

- 将 `Kobra-S1/ACEPRO` 的 USB 拓扑自动编号改为配置顺序编号；拓扑只做校验和诊断。
- 将每设备身份和能力写入 `ace.cfg` 的安装器托管设备节，避免逗号字符串和物理发现顺序决定工具号。
- 将本机换料准备、切刀、装载、卸载、擦嘴、位置恢复和错误处理宏集中到 `ace.cfg`；旧 `ace_machine.cfg` 只作为迁移输入。
- 将共享路径到打印头的加载和退出拆为受控机器宏入口；通用核心不猜测坐标、温度或挤出机运动。
- 将所有动作加入打印状态、路径锁、能力和 `physical_actions_enabled` 校验。
- 将 ACE2 物理动作保留在适配器中，但首版强制只读。
- 将界面状态统一为多设备数组，用顶部设备选择器驱动一个 V2 风格单设备管理组件。

### 剔除

- Kobra S1/K3/K3M 专属配置、引脚、坐标、停靠点、擦嘴和固定温度。
- SV08 专属 `PE9` 等传感器 pin 和特定 MCU 对象。
- 通过描述字符串寻找第一个串口的连接逻辑。
- 未经通用 Klipper 验证的厂家私有 API。
- V2 的单设备假设、固定 `TOOL=-1..3`、重复注册 `T0-T3/TR` 和前端任意 G-code 回退。

以后新增代码必须在提交说明中标记来源：`Kobra-S1/ACEPRO` 架构、SV08 行为、V3 新实现或机器适配层。

## 5. 配置迁移与安装规则

- `printer.cfg` 只 include `ace.cfg`；`ace.cfg` 不得再 include 任何 ACE 配置碎片。运行时只有这一条配置链。
- 新安装时，安装器根据用户选择在 `ace.cfg` 内生成或注释硬件拓扑区域，不创建 `ace_hardware.cfg` 或 `ace_machine.cfg`。
- 升级时，若发现旧 `ace_hardware.cfg`，安装器只读取一次并把硬件身份、通信参数和设备安全开关合并到 `ace.cfg`；成功后将原文件以不覆盖历史的名称归档到 `.ace-driver-v3/legacy/`，同时移除所有旧 include。
- 升级时，若发现旧 `ace_machine.cfg`，安装器使用 `merged` 迁移模式，把旧机器宏、校准变量和适用的自定义 G-code 合并到 `ace.cfg` 的七宏结构；七个名称绑定统一启用，用户物理宏内容及其注释/启用状态继续保留。归档已存在时不得覆盖，必须停止并报告冲突。
- 增删 ACE、修改 ACE1/ACE2 组合或调整设备拓扑时重新运行安装命令；工具映射按配置顺序稳定保持。
- 硬件拓扑块的结构、逻辑编号和设备通信身份由安装器管理；`enabled`、`rfid_enabled` 和 `physical_actions_enabled` 必须按稳定硬件身份继承，设备换序不能串位，新设备不能继承被移除设备的授权。
- 安装器不得自动重启服务，也不得执行送丝、回抽、切刀、加热或换料等物理动作。
- 全新安装写入 `toolchange_mode: manual` 和 `physical_actions_enabled: False`；重装不得覆盖用户已经选择的运行模式或已验证的设备物理动作开关。

任何后续代码、模板或测试不得重新引入活动 `ace_hardware.cfg` 或 `ace_machine.cfg`。设备拓扑只能写入 `ace.cfg` 的安装器托管区域，不得散落到共享参数或机器宏区域。

## 6. 用户体验要求

- 单 ACE 与多 ACE 的按钮位置和操作语义保持一致；多设备时只增加顶部设备切换，不堆叠多套控制区。
- 未配置、离线、能力不支持和被安全门禁的状态必须可区分。
- 长耗材动作必须显示进行中、成功、失败和可恢复建议。
- 设备掉线不得改变工具编号，也不得自动切换到另一台设备。
- 状态刷新不得触发换料或同步物理查询。
- Fluidd 卡片和独立控制界面必须显示同一当前工具、设备状态和动作阻塞原因。
- 单 ACE 视图必须按“ACE -> 总五通 -> 打印头”显示且隐藏一级五通；多 ACE 才显示“ACE -> 一级五通 -> 总五通 -> 打印头”，一级五通随设备切换。
- 共享编码器状态不随设备切换，必须分别显示 ACE 动作模式和打印监测模式，区分未配置、未校准、校准中、监测、保护、暂停策略和故障；不得把编码器无脉冲直接显示为“无料”。
- 编码器人工校准使用可取消的分步向导，步骤必须明确说明由用户手动推动耗材；界面不得暗示驱动会自动送丝。打印故障提示按事件序号去重，并展示工具、设备、路径与传感器现场及非确定性的可能原因。
- 下方传感器必须显示当前策略：默认 `toolhead_sensor_bypass: True` 时标为“仅监测”，显式设为 `False` 时标为“参与控制”。未接线时显示“未配置”，且不能暗示下方传感器是通用必装项。界面应单独显示上方传感器交接状态、挤出机标定距离、`upper_sensor_feed_timeout` 以及编码器的 `monitor/protect` 与最低跟随比例。
- 手动模式使用中性状态“手动模式”，隐藏或禁用自动换料、无限续料和自动切刀，不得把缺少换料宏显示为红色设备错误。
- 单 ACE 手动模式必须支持选择一个槽位启用或停用 ACE 内置辅助送料；多 ACE 仍受全局单路径锁约束。
- 自动换料未配置或未就绪时，`T0-T15` 和 `TR` 必须作为安全空操作返回：不调用宏、不获取路径锁、不改变当前工具和路径状态、不拒绝命令，也不暂停打印。每次收到工具指令时，两套前端都弹出“无法进行多色打印，仅可使用已启用的 ACE 内置辅助送料”提示，不做任务内去重。

## 7. 机器宏模板规范

每个宏上方只保留一个紧凑说明块，连续写明“用途、调用时机、物理动作、必须检查、默认状态”，段内不插入空行。危险宏再增加一行强警告，直接说明可能造成的机械后果。每个活动宏还必须有简短中文 `description`。说明必须是面向首次使用者的普通中文，不使用 ASCII 字画、星级风险评分、开发过程口吻或空泛重复语句。

每个说明块必须直接写出宏名称和定位。`_ace_prepare_toolchange`、`_ace_cut_filament`、`_ace_load_filament_to_toolhead`、`_ace_unload_filament_from_toolhead`、`_ace_wipe_nozzle`、`_ace_restore_after_toolchange` 和 `_ace_pause_on_toolchange_error` 七项全部为自动换料必用能力。不能只写作用而省略名称，也不能用长短不一的临时标题代替固定名称。

七个宏的名称行和 `[ace_machine]` 绑定注释必须统一使用 `!!!【必用】`，表示自动换料缺少任一能力即不可用。危险动作的警告行只写“严重警告”，不复用该标记。`!!!` 是文档层的醒目标识，后端仍必须独立完成绑定、宏注册和就绪检查。

V3 不采用尖端成型。七个名称绑定全部默认启用，但绑定只建立调用契约，不会激活样板坐标。任一实现缺失时自动换料保持未就绪，Klipper、手动模式和已授权的 ACE 内置辅助送料仍应正常工作；代码不得通过删除绑定绕过预检。

需要本机坐标或运动的 `_ace_prepare_toolchange`、`_ace_cut_filament`、`_ace_wipe_nozzle` 和 `_ace_restore_after_toolchange` 必须提供完整的注释样板；四个名称绑定仍保持启用。V2 实机中的停车、抬升、温度、切刀和清洁流程只用于形成样板；其中的具体值保持注释，且必须明确禁止其他机器照搬。

`_ace_load_filament_to_toolhead`、`_ace_unload_filament_from_toolhead` 和 `_ace_pause_on_toolchange_error` 不得留空。前两个继续作为 Python 路径控制器的受控入口，不能改成普通 Jinja 送料循环；错误处理只负责清楚提示并按打印状态暂停。任何宏迁移都必须同步更新配置解析、安装器、升级器、发布校验和测试。

## 8. 验证规则

本地验证与真机验证必须分开记录：

- 本地验证可以覆盖配置解析、迁移、模板契约、协议模拟、Python/Node 测试、发布树和安装器 dry-run。
- 真机验证必须单独记录目标打印机、部署版本、服务状态、配置加载、只读轮询和每个物理动作；模拟测试不得替代真机验收。
- 修改打印机配置、驱动链接或服务前必须先做变更前备份；变更后完成语法、服务和状态检查后再做变更后备份。
- 重启服务或执行可能引发物理动作前先确认 `print_stats`；打印中不得重启、换料、切刀或回抽。
- 只读状态正常不等于送料、回抽、切刀或换料安全可用。任何路径未知、上方/五通等权威传感器矛盾或动作失败都必须进入人工检查状态；下方传感器的缺失、未触发或原始跳变只用于观察，不得单独阻塞自动换料。
- 配置测试必须覆盖全新手动模式、未配置机器宏但正常启动、自动模式未就绪、按硬件身份保留 `enabled`/RFID/物理动作开关、七个宏迁移和单活动辅助送料。
- 命令测试必须覆盖未就绪状态下 `T0`、`T1-T15` 和 `TR` 全部无物理动作、无状态变更、不拒绝命令且不暂停打印，并验证每条工具指令都会产生一次前端提示。
- 辅助送料测试必须覆盖打印中缺少 `CONFIRM=1` 时拒绝、Moonraker 确认贯通、自动装载前停用旧槽位，以及停用失败时不启动新槽位。
- 五通测试必须覆盖单 ACE 完全忽略一级五通引脚和距离，以及 2-4 台设备的全部传感器、仅总五通、一级传感器空引脚、每设备距离独立、搜索超限和跨设备清空顺序。
- 传感器交接测试必须证明：ACE 命令距离不进入位置结论；上方传感器稳定触发是唯一 ACE 送料成功终点；预设参考量耗尽后继续有限分段但绝不越过 `upper_sensor_feed_timeout`；固件提前返回完成仍保留传感器宽限；截止时间后的迟到触发不得反转失败；传感器读取异常必须补发停机。旁路为 `True` 时下方未接线、未触发或随机跳变均不改变五类判定；旁路显式为 `False` 时恢复下方闭环并拒绝缺失/无效配置；挤出机只在上方稳定触发后接管；默认旁路卸载到上方释放后才交给 ACE 清空五通路径。
- 编码器测试必须覆盖空引脚默认关闭、有效引脚固定内部名称、旧显式 name 兼容、ACE 寻位与挤出机接管、动作和打印监测模式、`150 mm x 3` 校准及取消、`5%/10%` 阈值、单段脉冲不足、检测长度边界、物理挤出位置采样、回抽/恢复、脉冲重置余量、每故障单事件、`pause` 单次暂停、`monitor` 只提示、`protect` 中止并禁止标记已装载，以及任何故障都不触发无上限自动补料。模拟测试不能替代真实接线和动作验收。
